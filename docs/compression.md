# 压缩失败阶梯与可自定义提示词（P4.3）

> 状态：**设计已定，未实现**。本文只钉形状与提示词，代码在 `core::compress` 之后接。
> 原则沿用 D44/D49/D90/D97：判定只在"造请求前"与"生成结束"，压缩**不可重入**，
> 覆盖率不达标就是失败，不"大概齐"。

## 1. 失败阶梯（L0 → L4）

一档失败就往下掉一档，掉到底就**明说没有压缩**，不假装压过。

| 档 | 名字 | 做什么 | 失败判据 | 掉到 |
|---|---|---|---|---|
| L0 | 多步压缩 | 现状：四件草稿工具（append/edit/read/done）+ 冻结快照 + 覆盖率校验 | 调用失败 / 覆盖率不合格 / 超预算 / 结构不合法 | L1 |
| L1 | **备用多步** | 两趟：① 剔除思考块后压事实层；② 把思考块要点与 ① 的稿**合并再压一次** | 同上，且 Pass B 输入超预算的 0.6 就直接跳 L2 | L2 |
| L2 | 单步压缩 | 一遍出稿，结构约束最严（只有一次机会） | 调用失败 / 覆盖率不合格 | L3 |
| L3 | 分段压缩 | 切成约 16 段，逐段走 L0，再合并、去重、丢低置信 | 调用失败 / 合并后覆盖率不合格 | L4 |
| L4 | 确定性兜底 | 截断 + `incomplete` 声明（已有） | — | 结束 |

倒退档**只允许一次**：L3 的每一段自己可以掉到 L1/L2，但不允许"段的段"再分段。
否则最坏情况是 4×16 次调用，把用户的额度烧穿。
每次调用都走**冻结模型**（D76），不要在 4 段之间换模型——风格会不一致。

### 1.1 L1 的两趟具体做法

- **Pass A（`compress.fallback.strip`）**：输入里思考块已被**剥离**（不是删掉，是移出本轮输入），
  只压"发生了什么、结论是什么、还差什么"。这一趟不要求保留推理过程。
- **Pass B（`compress.fallback.merge`）**：把 Pass A 的稿 + 思考块的**要点**（由同一模型先抽成
  短要点，禁原文照搬）一起再压。产物是最终稿，每条带 `sources`（原文锚点 id）。
- 预算闸：`tokens(Pass A 输入) + tokens(思考块要点) > 0.6 × 窗口` → 不做 Pass B，直接 L2。
  理由：Pass B 会把相当一部分原文处理第二次，最坏情况压缩本身就把窗口吃掉。

### 1.2 L3 分段：段边界必须落在原子单元上

**不能按消息数硬切**。原子单元不变量是 `assistant(tool_calls[n]) + 全部 tool_result[n]`
才算闭合；切在中间会得到"有结果没发起"或"有发起没结果"的鬼话。

做法：

1. 按原子单元把历史聚成 N≈16 份（**份数是结果，不是输入**）。聚合用"时间 + 话题粗相似"，
   不追求最优解。
2. 压缩窗口是 1–5 / 5–9 / 9–13 / 13–16，**端点重叠**。重叠的段**只当上下文**：
   第 2 段把第 5 份原文作为"上文"附上，但不把第 5 份算进第 2 段的产出——否则第 5 份被压两遍，
   token 翻倍，还可能出两版说法。
3. 每段走 L0，产出段稿 + `sources` + `confidence`。
4. 合并（`compress.merge_segments`）：按时间拼、交叠处去重、冲突处保留**更接近原文**的一版并标记，
   丢掉低置信条目，输出丢弃清单。
5. 合并后过一遍覆盖率：合并稿必须覆盖所有段的 `sources` 并集，缺一个就是失败 → L4。

### 1.3 "置信度"必须可检验，不能只靠模型自评

模型对自己输出普遍过自信，0–1 自评不可校准。所以拆成三个可算的东西，加权：

| 因子 | 权重 | 怎么算 | 谁来算 |
|---|---|---|---|
| 硬事实命中 | 0.45 | 稿里的数字/路径/ID/版本号，必须能在原文里字符串命中 | 代码，不问模型 |
| 锚点覆盖 | 0.35 | 该条目 `sources` 引到的原文条数，以及是否被其他段引用 | 代码 |
| 模型自评 | 0.20 | `confidence` 字段 | 模型 |

低于阈值（默认 **0.5**，可配）且**没有被任何其他段引用**的条目丢弃。
阈值只拉低不拉高：压得保守最多是长，压得激进就是丢事实。

## 2. 提示词（全部可自定义）

放在设置 →「默认模型和场景提示词」。每条都存：`id / title / body / version / modified / updated_at`，
改过的标 `modified` 并给「恢复默认」。带 `{{}}` 的占位符在保存前校验：
缺一个就**拒绝保存**并指名缺哪个（提示词少了 `{{anchors}}` 不会报错，只会静默变差）。

### 2.1 `compress.draft`（L0，多步压缩）

```text
你在压缩一段对话的历史，压缩后会替换掉原文，成为之后唯一能看到的上下文。
你可以用四个工具：append（追加一节）、edit（改写已有节）、read（回看自己写的）、done（提交）。

要求：
1. 先 read 一遍已有草稿，再决定 append 还是 edit，不要重复写同一件事。
2. 每条结论后面写 sources=[原文锚点 id，逗号分隔]。没有锚点的条目不要写。
3. 数字、路径、命令、错误码、版本号必须逐字保留，不做同义改写。
4. 不确定的事标"待确认"，不要补全成确定句。
5. 用户明确说过的偏好与禁令单独一节，原样保留语义。
6. 写完调 done。不要输出与草稿无关的话。

必须覆盖：{{must_keep}}
已有草稿：{{draft}}
待压缩的原文：{{history}}
```

### 2.2 `compress.fallback.strip`（L1 Pass A）

```text
这一轮只压缩"事实层"：思考过程已经被移出，你看不到，也不要猜它写了什么。

写清楚四件事：
1. 发生了什么（按时间，只写有结果的步骤）
2. 得出了什么结论（每条带 sources）
3. 还差什么 / 什么被否决了及理由
4. 用户明确说过的要求与禁令

不要写"我推测""想必""应该是"。原文里没有的信息一律不写。
硬事实逐字照抄：数字、路径、命令、错误码、版本号。
每条的 confidence 按"这句话有多少直接证据"给 0–1，证据不足就给低分，不要客气。

必须覆盖：{{must_keep}}
原文（已剔除思考块）：{{history}}
```

### 2.3 `compress.fallback.merge`（L1 Pass B）

```text
把两份材料合成一份最终稿：
- A：事实层压缩稿（带 sources 与 confidence）
- B：被移出的思考过程的要点（已抽成短句，不是原文）

规则：
1. A 里的事实一条都不许丢；B 只用来补"为什么这么做"，不能改事实。
2. B 与 A 冲突时，以 A 为准，并在该条后面标 [冲突：B 说 …]。
3. 合并后按时间重排；同一件事只留一处，保留信息更全的那版。
4. 每条仍要带 sources 与 confidence。B 单独支撑的条目 confidence 不超过 0.6。

A：{{draft_facts}}
B：{{thought_points}}
```

### 2.4 `compress.single`（L2，单步）

```text
只有一次机会，直接输出最终稿，不要再问、不要分步。

结构固定四节：① 目标 ② 结论与决定（每条带 sources）③ 硬事实（逐字）④ 未完成与下一步。
硬约束：总长不超过 {{budget}} token；数字/路径/命令/错误码一字不改；
原文没有的不写；不确定标"待确认"。

必须覆盖：{{must_keep}}
原文：{{history}}
```

### 2.5 `compress.segment`（L3，逐段）

```text
你只负责这一段（第 {{index}} 段，共 {{total}} 段）。上面的"上下文"是前后相邻段的原文，
只用来判断指代（"它""那个文件"到底指谁），**不要把上下文里的内容写进你的产出**。

产出：
1. 这一段的事实与结论（每条带 sources 与 confidence）
2. 这一段里跨到下一段还没完的事，单列"未完"（下一段会接）
3. 提到但本段没定义的名词，单列"待指代"

上下文（仅供消歧）：{{context}}
本段原文：{{segment}}
```

### 2.6 `compress.merge_segments`（L3 合并）

```text
下面是一段历史的分段压缩稿，按顺序给出。请合成一份最终稿。

必须做：
1. 交叠区去重：同一件事只留一处，保留信息更全的那版。
2. 冲突处理：以更接近原文的版本为准，并在该条后标 [冲突：另一段说 …]。
3. 丢掉低置信条目：三个因子里硬事实未命中、锚点覆盖为 0、自评 < 0.5 的，直接删，
   并在"丢弃清单"里写清丢了什么、为什么。
4. 顺序按时间；每节最多 {{max_lines}} 行。
5. 输出两段：`## 最终稿` 与 `## 丢弃清单`。

分段稿：{{segments}}
```

### 2.7 `compress.verify`（质检，只查不改）

```text
不要改写任何内容。只做一件事：检查压缩稿有没有丢掉原文里的硬事实。
逐条比对数字、路径、命令、错误码、版本号、人名/文件名，输出缺失清单（每条一行）。
没有缺失就输出"OK"。
原文：{{history}}
压缩稿：{{draft}}
```

## 3. 设置里的形状

| key | 场景 | 必填占位符 | 可禁用 |
|---|---|---|---|
| `compress.draft` | L0 多步 | `{{must_keep}}` `{{draft}}` `{{history}}` | 否 |
| `compress.fallback.strip` | L1 A | `{{must_keep}}` `{{history}}` | 是（禁用则跳 L2） |
| `compress.fallback.merge` | L1 B | `{{draft_facts}}` `{{thought_points}}` | 是 |
| `compress.single` | L2 | `{{budget}}` `{{must_keep}}` `{{history}}` | 否 |
| `compress.segment` | L3 段 | `{{index}}` `{{total}}` `{{context}}` `{{segment}}` | 是（禁用则跳 L4） |
| `compress.merge_segments` | L3 合并 | `{{segments}}` `{{max_lines}}` | 是 |
| `compress.verify` | 质检 | `{{history}}` `{{draft}}` | 是（默认关，多一次调用） |

另有两个数值项，不在提示词里：`confidence_threshold`（默认 0.5）、
`segment_target`（默认 16，实际份数由原子单元聚合结果决定）、`pass_b_budget_ratio`（默认 0.6）。
