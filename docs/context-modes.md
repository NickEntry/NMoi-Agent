# 上下文档位（F1–F4）与压缩参数（设计稿，未动工）

> 用户 2026-11-02：「压缩相关参数，和当前上下文管理档位切换（F1~F4）也要在设置的应用设置里面」。

先把两个容易混的东西分开：

- **档位 F1–F4**：**一条内容留多少**。用户要切的是这个，一个旋钮，从"全文"到"只留指针"。
- **模式 1–4**（`context-modes-design-v1.1.md` 里那四个）：**谁来决定怎么处理**——全量保留 /
  内容形态 / 语义判断 / 灰烬。模式 3、4 要模型参与，是另一层，这一批不做。

这一批只做**档位**。它其实就是"模式 2 的强度"，但用一个 1–4 的旋钮表达，
比让用户先理解四个模式再选要直接得多。

## 1. 现在实现到哪（读代码）

| 件 | 状态 |
|---|---|
| `core::budget` | 有：建议线默认 0.75、绝对线 0.92、`reserve_fixed`（D144） |
| `core::router` | 有：`route()` 纯函数，阈值 2k / 8k / 32k，头尾各 1k；**没接进请求组装** |
| `core::form` | 有：`render_for_form()` 把归档条目渲染成 F1–F5；**没接** |
| `core::archive` | 有：内容寻址归档；压缩在用，路由没用 |
| 设置页 | 只有「默认上下文窗口」；建议线/绝对线还是灰字 |

结论：**档位这个概念只存在于设计文档里；参数全是 core 里的常量，界面上改不了。**

## 2. 一个旋钮：F1–F4

设置 → 应用设置 →「上下文管理」：

```
上下文档位
  ( ) F1 全文      一律发原文，不裁（现在就是这样）
  ( ) F2 截断      大块内容只留头尾，加一行"已归档 ref#…"
  ( ) F3 占位      大块内容换成一行占位符，原文进归档
  ( ) F4 指针      只留一行索引（来源、行号范围、一句描述）

压缩
  建议线 / 绝对线 / 给输出留

内容形态（档位 ≥ F2 时可调，F1 时灰着）
  小 / 大 / 超大 阈值，头 / 尾 保留量
```

档位是**上限**，不是"一律按这个来"：router 仍然按内容类型逐条判，但**结果不许超过档位**。
比如档位 F2 时，40k 的日志按规则本该给 F4，被夹到 F2（头 1k + 尾 1k）。

| 档位 | 2k 以下 | 2k–8k | 8k–32k | 32k 以上 |
|---|---|---|---|---|
| F1 | 全文 | 全文 | 全文 | 全文 |
| F2 | 全文 | 全文（代码类可截断） | 头 1k + 尾 1k | 头 1k + 尾 1k |
| F3 | 全文 | 全文 | 占位符 | 占位符 |
| F4 | 全文 | 指针 | 指针 | 指针 |

**无论档位多高，这几类永远 F1**（设计文档 §2.3.1 的硬规则）：

1. 用户自己说的话、系统提示、工具定义；
2. 被标 `protected` 的内容（失败、报错、异常）；
3. 这一轮**还没被消费**的最新一条工具结果（模型正要读它，换成指针等于没给它）。

没有这三条兜底，F4 会把用户的原话也换成一行指针——那不是省 token，是把对话弄坏。

## 3. 参数

| 界面 | core | 默认 |
|---|---|---|
| 建议线 | `BudgetLines.suggest` | 75% |
| 绝对线 | `BudgetLines.absolute` | 92% |
| 给输出留 | `Budget::reserve_output` | 模型 `max_tokens`，夹 1024–8192 |
| 小 / 大 / 超大 | `RouterConfig::{small,large,huge}_threshold` | 2 000 / 8 000 / 32 000 |
| 头 / 尾 | `RouterConfig::{truncate_head,truncate_tail}` | 1 000 / 1 000 |

- 档位 F1 时，内容形态那五项**灰着**（用不上），但值仍然保留——切回 F2 还是上次那份。
- 每个数字旁边写实际值：`建议线 75%（128k 窗口 ≈ 96k token）`。
- 改完立即生效（下一轮请求就用），不设"保存"。

存 `settings` 表（跟着库走），一条 JSON：

```json
{"context":{"form":"F2","suggest":0.75,"absolute":0.92,
 "router":{"small":2000,"large":8000,"huge":32000,"head":1000,"tail":1000}}}
```

## 4. 切档位不改写历史

- F1 → F2：只影响**之后**新进来的内容；已有历史不动（要它变小就手动压一次）。
- F2 → F1：之后全给全文；**已经截断过的保持截断**（原文在归档里，点开能回灌）。
- 设置页把这两句写出来，别让用户以为切一下旧消息就变回去了。

## 5. 会话级覆盖（先不做）

全局一个档位。会话级覆盖（长任务临时切 F4）以后放聊天页的上下文面板，
存 `conversations.context_form`（NULL = 跟全局）。这一批不做，避免三处都能配。

## 6. 落地顺序

1. **0.15aq-a**：设置页 + 档位 F1 + 三个压缩参数（建议线/绝对线/输出预留）接进 `Budget`。
   这一批不碰 router，行为与现在一致，只是参数能改了。
2. **0.15aq-b**：`router` / `form` / `archive` 接进 `run_session_turn`，档位 F2–F4 生效
   （含"永不路由"三条兜底）；工具卡上标出这一条被换成了哪一档 + 归档 ref。
3. 之后：模式 3 / 4（要模型参与），那时才在设置里出现第二组选项。

## 7. 验收

1. 建议线改 60%：下一轮在 60% 就出压缩信号（日志 `trigger=Suggest`）。
2. 档位 F1：一条 40k 的工具结果原样进请求。
3. 档位 F2：同一条变成头 1k + 尾 1k + 尾注；工具卡上能看到 ref。
4. 档位 F4：同一条只剩一行指针；**用户自己的消息仍然是全文**。
5. 报错的那条工具结果，在 F4 下仍然是全文（protected）。
6. 切回 F1：之后新内容全文；老的那条仍是截断（原文从归档能点开）。
7. 杀进程重开：档位与参数还在。
