# 上下文管理：档位与参数（设计稿，未动工）

> 用户 2026-11-02：「压缩相关参数，和当前上下文管理档位切换（F1~F4）也要在设置的应用设置里面」。

先把两个容易混的东西分开，不然后面全是歧义：

- **档位（模式 1–4）**：一整轮对话**用什么策略**处理上下文。这是用户要切的那个。
- **F1–F5**：单条内容**长什么样**（全文 / 截断 / 占位 / 指针 / 索引）。它是档位 2 内部
  按规则自动选的结果，不是用户手动切的东西。

`context-modes-design-v1.1.md` 里四个模式是：1 全量保留、2 内容形态、3 语义判断、4 灰烬。
F1–F5 是模式 2 的产物。设置页按这个分：**上面切档位，下面调参数**。

## 1. 现在实现到哪（读代码）

| 件 | 状态 |
|---|---|
| `core::budget` | 有：`Threshold`（百分比 / 绝对值）、建议线默认 0.75、绝对线默认 0.92、`reserve_fixed`（D144） |
| `core::router` | 有：`route()` 纯函数，阈值默认 2k / 8k / 32k，头尾各 1k；**没接进请求组装** |
| `core::form` | 有：`render_for_form()` 把归档条目渲染成 F1–F5；**没接** |
| `core::archive` | 有：内容寻址的归档；压缩在用它，路由没用 |
| `core::compress` | 有：压缩循环、覆盖率校验、摘要注入 |
| 设置页 | 只有「默认上下文窗口」和「允许新版本」；建议线/绝对线仍是 `pendingRows` 里的灰字 |

结论：**参数在 core 里都是常量，界面上一个都改不了；档位这个概念只存在于设计文档里。**

## 2. 设置页长什么样

设置 → 应用设置 → **上下文管理**（新的一张卡，放在「默认上下文窗口」下面）：

```
档位
  ( ) 1 全量保留    什么都不裁；只在绝对线前压一次（现在就是这一档）
  ( ) 2 内容形态    按规则把大块内容换成截断/占位/指针（F1–F5）
  ( ) 3 语义判断    让模型判断"什么没用了"（未实现，灰着并写差什么）
  ( ) 4 灰烬        给模型完全编辑权（未实现，灰着）

压缩
  建议线        [ 75 ] %     ← 到这儿先压一轮
  绝对线        [ 92 ] %     ← 到这儿先压再发；生成中过线就截断
  给输出留      [ 自动 ]     ← 自动 = 模型 max_tokens，夹在 1024–8192

内容形态（只在档位 2 生效）
  小内容上限    [ 2000 ] token
  大内容上限    [ 8000 ] token
  超大内容上限  [ 32000 ] token
  截断保留头部  [ 1000 ] token
  截断保留尾部  [ 1000 ] token
```

- 档位用**单选列表**（四个都摆出来），不是下拉：四个选项、每个一行说明，收进下拉等于藏起来。
- 3 / 4 未实现：**整行灰 + 副标题写差什么**（「要模型参与判断，等 0.16」），
  点了给一句提示，不假装能选。
- 参数改动**立即生效**（下一轮请求就用新值），不设"保存"按钮——这一页没有需要原子提交的东西。
- 每个数字旁边写当前实际值：`建议线 75%（128k 窗口 ≈ 96k token）`。

## 3. 参数落到哪

| 界面 | core 里对应的东西 | 现在的值 |
|---|---|---|
| 建议线 | `BudgetLines.suggest` | `Threshold::percent(0.75)` |
| 绝对线 | `BudgetLines.absolute` | `Threshold::percent(0.92)` |
| 给输出留 | `Budget::reserve_output` | 模型 `max_tokens`，夹 1024–8192 |
| 小/大/超大 | `RouterConfig::{small,large,huge}_threshold` | 2 000 / 8 000 / 32 000 |
| 头/尾 | `RouterConfig::{truncate_head,truncate_tail}` | 1 000 / 1 000 |

存哪：`settings` 表（跟着库走），不是 SharedPreferences。理由：这些参数**决定请求长什么样**，
换设备导入一份库就该带着走；窗口默认值那种"这台机器的偏好"才放本地。

键名（一条 JSON，别开七个键）：

```json
{"context":{"mode":2,"suggest":0.75,"absolute":0.92,
 "router":{"small":2000,"large":8000,"huge":32000,"head":1000,"tail":1000}}}
```

## 4. 档位怎么切（这是这一批最要紧的取舍）

- **切档位不改写历史**。模式 2 是"内容进来时就决定形态"，所以：
  - 1 → 2：只影响**之后**新进来的工具结果；已有的历史不动（想让它也变，得手动压一次）。
  - 2 → 1：之后进来的全给全文；已经截断过的那几条**保持截断**（原文在归档里，点开能回灌）。
  - 设置页那句说明要写出来，别让用户以为切一下旧消息就变回去了。
- **档位 2 需要先把 router/form 接进请求组装**（现在没接）。所以落地顺序是：
  先做设置页 + 档位 1 的参数（建议线/绝对线/输出预留），再做档位 2 的接线。
- **档位 3 / 4 先不出现"能选"的样子**：灰行 + 差什么。`不给假开关`。

## 6. 验收

1. 设置里把建议线改成 60%：下一轮请求在 60% 就出压缩信号（日志里 `trigger=Suggest`）。
2. 绝对线改成 90%：`used/usable` 的判定跟着变。
3. 档位选 1：行为与现在一致（不裁内容）。
4. 档位选 2（接线之后）：一条 40k token 的工具结果在请求里变成指针形态；
   面板上能看到它被换成了哪一档、归档 ref 是什么。
5. 档位 3 / 4：灰着，点了给"差什么"，不会真的切过去。
6. 改完参数杀进程重开：值还在（存在 `settings` 表里）。
