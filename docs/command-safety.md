# 命令执行前询问（0.17a 设计稿，未动工）

用户 2026-11-12：「弄个命令执行询问开关，这个开关打开的时候还会有一个开关显示出来，
"黑名单模式"，这个打开后只有黑名单里面的命令才会询问，比如 rm 什么的」，
并给了一份别家客户端的安全规则分组截图（十组、75 条，每组一个开关）。
同一天追加：「只匹配命令开头不太对，不如改成命令 + 参数，比如 `rm -*r`——
AI 调用的不一定是 `-rf`，也可能是 `-fr`」，并提醒「正则规则要有长度限制，`*` 会失误，
可以用 `.{0,15}` 这种」。

这一份是计划，不是实现。里面标「待拍板」的三处需要用户点头。

---

## 1. 两个开关，两个层级

**能力开关**（已有，`crates/core/src/policy.rs`）：`NativeShell` / `ContainerExec`。
它回答「这个助手能不能用命令」——默认关，要在助手页显式打开。

**询问开关**（新，两个）：

| 开关 | 键 | 默认 | 语义 |
|---|---|---|---|
| 命令执行前询问 | `shell.ask` | **开** | 每条命令执行前问一句 |
| 黑名单模式 | `shell.blacklist_mode` | **开** | 只问命中规则的；关掉 = 一律问 |

两个都在**能力开关打开之后才有意义**。所以界面上它们挂在能力开关下面：
能力关着时这两行照摆但灰（不藏——藏起来会让人以为没有这个功能；也不挂解释性小字）。

为什么两个默认都开：能力开关默认关，用户手动打开它，说明他知道自己在放开什么；
这时候「每条命令都问」是安全的默认，而「黑名单模式」把打扰降到只问危险的。
反过来（默认不问）等于用户一打开能力就全放行，而那条能力开关的字面意思只是"能用"。

## 2. 规则表

沿用截图那十组、75 条，作为内置规则（`assets/shell-rules.json`，随 APK 发，不进库）：

| 组 | 条数 | 组内例子 |
|---|---|---|
| 磁盘操作 | 10 | `dd` `mkfs` `fdisk` `parted` `format` `dd of=/dev/*` |
| 网络与防火墙 | 7 | `nc` `ncat` `socat` `iptables` `ufw` `firewall-cmd` |
| 系统服务 | 5 | `systemctl` `service` `chkconfig` `crontab` `at` |
| 用户管理 | 4 | `passwd` `usermod` `useradd` `userdel` |
| 文件删除 | 11 | `rm` `rmdir` `del` `find -delete` `find -exec rm` `Remove-Item -Recurse` |
| 权限 | 8 | `chmod` `chown` `chgrp` `attrib` `icacls` `chmod 777` |
| 进程控制 | 5 | `kill` `killall` `pkill` `taskkill` |
| Git 操作 | 11 | `git reset --hard` `git clean -f` `git push --force` `git branch -D` |
| 命令注入 | 11 | `; bash/sh -c` `&& bash -c` `\| bash/sh/zsh` `eval $()` `curl\|sh` |
| 脚本执行 | 3 | `python/node/ruby -c/-e` `bash/sh -c` |

**每组的开关 = 这一组要不要问**（关掉 = 这一组整体放行）。组开关是"批量少打扰"的手段，
不是"关掉就安全"——它跟单项一样，改了立刻生效，下一次命令就按新的走。

**自定义添加**：输入一个字面量或一条正则，选一个组挂进去（或建"自定义"组）。
保存时编译一次，编译不过就拒绝并说出错位置——**不静默丢弃**。

## 3. 匹配：三段式，不是 startsWith

规则项的形状是 `命令 + 参数模式`，但**判定不靠"字符串开头"**，也不靠一条很长的正则。
分三步，每步都能单独测：

### 3.1 拆

先按 `;` `&&` `||` `|` 和换行把整行拆成子命令。

不拆的后果有两个，都真实：`echo hi && rm -rf build` 里 `rm` 不在开头（开头匹配漏掉）；
而 `.{0,15}` 这类通配会把**下一条命令**垫进上一条的匹配窗口里（用一条无害命令把危险命令"包"进来，
或者反过来误伤）。

容器里跑的是 `sh -c "整行"`，所以整行只在这一层拆一次，拆完每条独立判。

### 3.2 归一化

- 去引号：`'rm' -rf x` → `rm -rf x`（不去的话加个引号就绕过）
- 折叠连续空白与制表符
- 剥掉套壳前缀：`sudo` `env` `command` `nohup` `time` `xargs`（`xargs rm` 是常见形态）
- 反斜杠转义按字面还原（`r\m` → `rm`）
- **不做变量展开**：`$X` 原样留着 → 认不出就走"问"，宁可多问一次

### 3.3 匹配

对每条子命令取 `argv[0]`（basename，`/bin/rm` → `rm`）找组，再对该组的项逐条判：

- **`literal`** 项：在归一化后的整条子命令里做子串匹配（`dd of=/dev/`、`curl|sh` 这种）。
- **`flags`** 项（内置的危险参数项走这一种，**不用正则**）：
  - 命令名相等，且 argv 里**任一**以 `-` 开头的短选项**含**某个字母，或含某个长选项。
  - `rm` 的判据写成：`{cmd: "rm", any_flag_chars: ["r", "R"], any_long: ["--recursive", "--force"]}`。
  - **与字母顺序无关**：`-rf` `-fr` `-vrf` `-R` `--recursive` 全命中；`rm -f -r x` 也命中
    （两个参数分别满足 `-f` 与 `-r`）。
  - 这一层是代码判定，不是正则——正则在"参数是字符集合"这件事上没有优势，
    而漏一个 `-fr` 的代价是一次不可撤销的删除。
- **`regex`** 项（只给自定义规则用）：见 §4。

`.{0,15}` 的定位要说清：它是**给用户自定义**的兜底写法（`rm\s+-.{0,15}r`），
不是内置规则的手段。内置项用 `flags` 判据，因为它不依赖"猜多远"。

### 3.4 为什么 `rm -.*r` 不对，`-\w*r` 也不够

- `rm -.*r`：`.` 跨空格 → `rm a.txt report.md` 里 `a.txt r` 也能凑出来 → 误杀（可接受），
  但没拆段时还会跨到下一条命令（不可接受）。
- `rm\s+-\w*[rR]`：`\w` 不跨空格，安全；但 `rm -f -r dir` 不命中（两个独立短选项）。
  所以内置不能只用正则，得看整个 argv。

## 4. 正则的约束（自定义规则）

- pattern ≤ **200 字符**，超了拒绝保存。
- 用 Rust `regex`（线性时间，没有回溯爆炸）；编译一次缓存，按 pattern 文本做键。
- 匹配前把子命令**截到 4096 字符**；更长的整条直接判"问"（长命令本身可疑）。
- 匹配不区分大小写。
- 编译失败 → 保存时立刻报错并指出第几个字符，不进表。

## 5. 三档结果：放行 / 询问 / 拒绝

拒绝（不是询问）只给极少数，写在同一个规则表里、同一个界面上能看见：

```
rm -rf /        rm -rf ~        dd of=/dev/sd*        mkfs.* /dev/sd*
```

判据是「删/写的是根、家目录、块设备」——这种命令没有"允许一次"的必要。
拒绝也必须**在界面上看得见、能改**，不做隐形闸（那条老规矩：闸一旦隐形，
撞上时用户看到的是"事情做了一半就停了"，而他什么都没做错）。

## 6. 询问界面

一行等宽的命令 + 命中的规则名（`文件删除 · rm -r`），下面三颗键：

1. **允许这一次**
2. **这个会话里不再问这一条**（内存里记，重启清空——它是临时决定，不是设置）
3. **拒绝**

60 秒没人点 = **拒绝**，并把「没等到回答」当成工具结果回给模型（`status = error`），
不是挂在那儿。这一条要写进判据：**超时绝不能等于允许**。

## 7. 数据流与落点

- 判定在 **core**（`crates/core/src/shellguard.rs`，纯函数 `decide(command, rules)`），
  不放在 Kotlin：默认关只有落到一个可测的判定函数上才靠得住（`policy.rs` 那句老话）。
- 询问的等待复用 `kills` 那套 `(session, call_id)` 登记表 + 条件变量（跟"单条关闭"同一个形状），
  不新开一套 IPC：`begin_ask(session, call_id, command, rule)` → 等 → `answer(session, call_id, verdict)`。
- FFI 加两个符号：`nmoi_tool_asks_json(session)`（现在有哪几条在等）与
  `nmoi_tool_answer_json(session, call_id, verdict)`。
- 界面上：跟"正在跑的工具调用"那一行同一个位置（半屏弹窗），不新开一层。

## 8. 诚实边界（要写进文档，也要写进界面文案）

黑名单永远不完备：`xargs rm`、脚本里的 `rm`、`find -exec`、PowerShell 别名、
容器里另一套命令名、写进 `.sh` 再 `bash` 跑。所以这个开关叫「只问清单里的」，
**不叫「安全模式」**——它是降低打扰的折衷，不是安全保证。这一句要出现在设置页里。

---

## 9. 判据

单测（`shellguard::tests`）：

1. 拆：`echo hi && rm -rf x` → 两条，第二条命中；`a; b | c` → 三条。
2. 归一化：`'rm' -rf x`、`sudo rm -rf x`、`xargs rm -rf` 都按 `rm` 判。
3. `-fr` / `-vrf` / `-R` / `--recursive` 全命中（顺序无关）。
4. `rm -f -r x` 命中（两个独立短选项）。
5. `rm --preserve-root file` 误命中——写成断言，标明"接受多问一次"。
6. `.{0,15}` 不跨命令：`echo rmxxxxxxxxxxxxxxx && ls` 不命中 `rm`。
7. 超长命令（>4096）→ 问。
8. 正则编译失败 → 保存被拒。
9. 模式：黑名单关 → 一律问；黑名单开 → 只问命中。
10. 超时 → 拒绝（不是允许）。

真机 **V138**（六步，见 `verification.md`）。

## 10. 不做

- 完整 shell 语法解析（引号、heredoc、函数、别名展开）——宁可多问一次。
- 变量展开与命令替换的求值（`$(...)` 只标"问"）。
- AST 级判据、把命令跑在沙箱里再观察（那是另一条线）。
