# 遮罩与边缘面板（Android）

侧栏、底部子窗口这类"压在聊天之上的层"，行为统一按这份文件来。不是每个面板各写一套——
一套手势、一套动画、一套返回逻辑，用户学一次就够。

## 1. 结构

```
┌─────────────────────────────┐
│  聊天（保持可读，不卸载）      │  ← 60% 黑色遮罩盖在它上面
│  ┌───────────────────────┐  │
│  │ 面板：从屏幕边缘伸出     │  │  ← 侧栏从左边缘、底部窗口从下边缘
│  └───────────────────────┘  │
└─────────────────────────────┘
```

- 聊天层**不销毁**：关掉面板要立刻回到原滚动位置。所以用叠加层而不是换目的地（导航）。
- 遮罩覆盖到系统栏下面（edge-to-edge），否则状态栏那一条会亮一块。
- 面板自己的圆角那一侧才贴边；贴屏幕边的那侧不圆角。

## 2. 遮罩

| 项 | 值 |
|---|---|
| 颜色 | 纯黑，alpha **0.60**（`0x99000000`） |
| 进入 | 0 → 0.60，跟面板同时开始 |
| 退出 | 0.60 → 0，比面板略快结束（面板先看不见、遮罩后消失） |
| 点击 | **关闭面板**（并归还焦点） |
| 滑动 | **不关闭**，见下 |

**滑动不关闭**是刻意的（2026-10-22 定）：面板里常常是长列表，从边缘往上滑时手指会先落在遮罩上，
一滑就关会让人以为"列表弹回去了"。

代价是手感像失灵，所以补一条：遮罩上拖动时给它 **8dp 的阻尼位移**（跟手 1/4 系数，
松手弹回原位）。位移看得见、但不产生关闭结果——这就把"我在动"和"它不动"分开了。

> 这条和"拖动面板边缘关闭"不冲突：**能关闭的拖动只发生在面板自己的拖柄/边缘上**，
> 遮罩上的拖动永远只是反馈。

**浅色主题**：同样 60% 黑。如果实机上显得发灰，把 alpha 降到 0.45 再观察——
值放在 `ThemeTokens.scrimAlpha` 一处，别在面板里各写各的。

## 3. 边缘伸出

| 面板 | 从哪条边 | 进入 | 退出 |
|---|---|---|---|
| 侧栏 | 左边缘 | 水平位移 `-width → 0` + 遮罩同时变深 | 反向 |
| 底部窗口 | 下边缘 | 垂直位移 `+height → 0`，先快后慢（`FastOutSlowIn`） | 反向 |

- 面板不做缩放、不做淡入——**只位移**。缩放会让里面的文字发虚，淡入会让人分不清"是新页面还是浮层"。
- 面板内第一帧就把内容布局好（`AnimatedVisibility` 里放已测量好的内容），避免边动边重排。

### 时长与系统动画缩放

**用 Compose 自带的动画（`AnimatedVisibility` / `animateFloatAsState` / `Animatable`），
不要自己乘系数。** Compose 的动画会读 `MotionDurationScale`（来自
`Settings.Global.ANIMATOR_DURATION_SCALE`），自动跟着系统的"动画时长缩放"走。
手动再乘一次，会变成"系统调 0.5×、实际 0.25×"。

- 基准：进入 **220ms**、退出 **180ms**、遮罩 **进入 220ms / 退出 160ms**。
- 用户把动画缩放关掉（0×）时，面板应**瞬间到位**、遮罩同时到位，不留一帧"半透明还在动"。

## 4. 动画期间不可点

面板从开始动到落位之间，里面的任何项都不接受点击。三个理由，不是洁癖：

1. 手指会误触：动画刚开始时用户在等的目标位置还没到。
2. 读屏会读到一半的界面：动画中焦点树应视为不可交互。
3. 连续点击会叠出两次导航。

做法（两条都要）：

- 交互：`clickable(enabled = settled)`；`settled` 由面板的动画状态给出，落位后置真。
- 无障碍：动画期间 `semantics { hideFromAccessibility() }`，落位后恢复。只关点击不关语义，
  读屏用户仍然能点到空气。

## 5. 关闭的三条路

| 触发 | 行为 |
|---|---|
| 点遮罩 | 关闭 |
| 拖动面板拖柄/贴边那一侧往屏幕边缘拖 | 过阈值就关闭，不过就弹回 |
| 系统返回（手势或按键） | 关闭 |

- **返回**：`BackHandler(enabled = open)`，注册在面板这一层，不要注册在 Activity——
  否则会先退出应用。面板开着时，返回只关面板。
- **Android 13+ 预测性返回**：`android:enableOnBackInvokedCallback="true"`。
  开了之后返回手势会有"预览"阶段；不实现渐进式返回也能用，但会先缩一下再弹回，
  看着像卡了一下。至少要把面板的关闭动画接到 `OnBackInvokedCallback` 上，
  别让它等到手势完成才开始动。
- **拖动关闭的门槛**：位移过面板尺寸的 **35%** 或甩动速度过 **800dp/s**，取先到的。
  不过门槛用 spring 弹回（`dampingRatio = 0.9`，不要用 tween——弹回是"物理"，不是"过渡"）。
- 拖动只在**拖柄**和**贴屏幕边的那一侧**生效：面板内容是长列表时，
  整面拖会和滚动打架（`nestedScroll` 能解，但"哪里能拖"比"什么时候能拖"更好解释）。
- 关掉之后把焦点还给聊天输入框（`FocusRequester`），否则键盘不会自己回来。

## 6. 状态与边界

- 同时只开**一个**面板。开第二个时先关掉第一个（不是叠两层遮罩——两层 60% 会变成 84%）。
- 面板开着时来通知/来电：只让系统层盖上去，面板保持原状，不要自己收。
- 面板开着时旋转屏幕：**收掉面板**并回到聊天。理由：面板宽度/高度按旧边算的，
  中途重算会出现"半开"的中间态，比重开一次更难受。
- 输入法：底部窗口打开时先收键盘（`WindowInsets.ime` 监听），关闭后再按需恢复——
  键盘 + 底部窗口同时出现会把可用高度压到只剩一条。

## 7. 令牌（放一处，别散在各面板里）

```
scrimAlpha              0.60        // 浅色主题若发灰降到 0.45
panelEnterMs            220
panelExitMs             180
scrimExitMs             160
scrimDragDamping        0.25f       // 遮罩上拖动的跟手系数
dismissFraction         0.35f       // 拖动关闭的位移门槛
dismissVelocityDp       800f        // 拖动关闭的速度门槛
springDampingRatio      0.9f
```

## 8. 还没做的

- 桌面端（GTK4 / WPF）的对应行为没定：桌面没有"从屏幕边缘滑出"的习惯，侧栏更常见是就地展开。
  等桌面外壳开工再写，别把移动端的手势硬套过去。
- 遮罩上的阻尼位移是这次新加的，实机上要确认它不会和面板的拖动视觉混在一起（两处都在动）。
