# UI 结构与页面归属（信息架构）

> 这份不写像素，只写**谁指向谁、怎么回去、一页放什么**。
> 动手之前先在这里落三行（入口 / 返回 / 子页），比事后补入口便宜得多——
> 2026-10-23 就踩过一次：功能写完了、代码也在跑，用户说"没看到"。

## 0. 三条硬规矩

1. **一页一件事。** 设置是"分组索引"，不是"所有开关的列表"。一页上堆了四类东西，
   用户就要在滚动里找，而且找不到的时候不知道是自己没滚到、还是根本没有。
2. **不给假开关、不给假表单。** 没接核心的项：灰行 + "待接 Px"。接了一半的项：
   能点的部分照常，不能点的部分写明差什么。**点了没反应比没有这个开关更坏。**
3. **每一页都写三行**：谁指向它 / 它怎么回去 / 它下面的子页怎么办。
   返回只在顶层注册一次，按**栈深**判断（D118），子页不各写一套。

## 0.5 参考对象：像的是布局与交互，不是像素

用户 2026-10-23 明确：**UI 布局和这些交互要和 kelivo / RikkaHub 很相似**——那是成熟的人类交互美学样本，
不是我们自己发明一套。像的是层级、间距节奏、行高、手势与返回习惯；不像的是像素与代码
（kelivo 是 AGPL，D15：一行代码都不能抄，只参考移动端的结构与行为）。

做每个页面前先对一遍这张表，对不上的地方要么改，要么写清为什么不一样：

| 场景 | 对齐点 |
|---|---|
| 设置 | 分组小标题 + 圆角卡片包行；行内左图标、右 chevron 或当前值；子页一项一张卡 |
| 列表 | 行高 56–64dp；分隔用间距而不是横线；右侧时间、预览单行省略 |
| 抽屉 | 从左滑出、遮罩 0.60、当前项高亮；任意页面都能滑出来（D119） |
| 输入岛 | 悬浮圆角；左「＋」右发送（同一按钮换形态）；上方一行状态（token / 模型 / 视觉覆盖） |
| 消息 | 用户右、助手左（可切全宽）；思考块折叠；工具调用折叠卡；压缩分界线 |
| 面板 | 底部上滑、点遮罩关闭、动画未落位不可点（D109） |
| 返回 | 左上角箭头，语义与系统返回一致，按栈深处理（D118） |
| 图标按钮 | 热区 48dp、视觉 22dp、`contentDescription` 必填（D103） |

## 2. 设置：从"六节平铺"改成"分组索引 + 子页"

目标形状（照 kelivo 的结构，不照像素）：**分组小标题 + 圆角卡片包住行 + 行内左图标右 chevron/当前值**。
索引页上**不摆开关**，只摆入口和"当前值摘要"；开关进各自的子页。

| 分组 | 子页 | 状态 |
|---|---|---|
| 外观 | 启动器图标（已实现）、**主题三态（已实现）**；**背景（纯色/图片/视频，按助手）** 下一步；自定义主题只有灰行+预览位 | 一半（见 `docs/ui/appearance.md`） |

## 3. 日志：三种通道，四个按钮，一个齿轮

形状（用户 2026-10-23 定）：

```
设置 → 调试 → 日志                        ← 索引页
  ├─ 上下文日志      12.4 KB / 8 MB   ●开  ›
  ├─ 请求日志        0 B    / 8 MB   ●开   ›
  ├─ 调试日志        84.1 KB / 8 MB  ●开  ›
  └─ 右上角 ⚙ → 日志设置页：三种各自的开关 + 上限档位（2/4/8/16/32 MB）
       点进任意一行 → 该通道子页：查看 / 复制 / 导出 / 清除 + 预览区（自己滚）
```

**为什么分三种**，不是加个"详细模式"：

| 通道 | 写什么 | 现在有没有生产者 | 默认 |
|---|---|---|---|
| 上下文 `context` | 组装过程：注入了哪些块、各来源 token、压缩轮次与前后对比、分界线位置 | **没有**（等 P4 真正接上压缩线） | 开，8 MB |
| 请求 `request` | HTTP：URL、状态码、耗时、重试次数、SSE 事件计数；header **脱敏**，body 只在"详细"开关下写 | **没有**（HTTP 层还没过 FFI 面） | 开，8 MB；body 关 |
| 调试 `debug` | 应用事件：启动、库、图标切换、原生层、崩溃前状态 | 有（现在 `NLog` 的调用点） | 开，8 MB |

三条理由：

- **量的差别**：一次请求能写几十行（重试、SSE 分片），混进调试日志会把"启动那五行"冲掉，
  而启动的那几行恰恰是排查时最常要的。
- **隐私的差别**：请求日志里有 header 和可能的 body，**默认必须脱敏**（密钥只留末尾 4 位，D28）；
  调试日志里不该出现这些东西，就不该共用同一个脱敏开关。
- **清理的差别**：清请求日志（常常是用来释放空间、或者清掉敏感内容）时，不该把调试日志一起清掉。

**没有生产者时界面要直说**："这一类还没有产生者（等 P7 HTTP 层）。"
给个空列表装正常，等于让用户以为"日志功能坏了"。

实现约定（改代码时照这个来）：

- 三个文件：`files/logs/{context,request,debug}.log`，各自轮转、各自上限、各自清理。
- 开关与上限存 `SharedPreferences`（`app_log`）：必须在第一行日志之前读到，
  settings 表要开库、要线程，够不上（D117 的同一个理由）。
- 四件事各自独立：查看只读尾部、复制进剪贴板、导出走 SAF、清除要二次确认。
