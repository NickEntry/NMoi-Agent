# 会话私有路径、跨会话访问、压缩继承（设计稿，2026-11-08）

> 用户 2026-11-08 口述。三件事一起做才有意义：**先有隔离**，才谈得上"跨会话访问"；
> 有了访问，才需要"哪个会话"这个身份能被复制出去。

## 1. 目录布局

| 现在 | 目标 |
|---|---|
| `files/sessions/<id>/chat`（会话自己的 /chat） | 不变 |
| `files/sessions/<id>/images` | 不变 |
| `/tmp`：全局（容器里的 `PROOT_TMP_DIR` 也是全局） | **`files/sessions/<id>/tmp`**，工具里的 `/tmp` 映射到它 |

- 工具里写 `/tmp/x` = 写 `sessions/<id>/tmp/x`，**别的会话看不见**（跟 Kelivo 一样）。
- 容器里那个 `/tmp` 仍是容器自己的（guest 的 `/tmp`），跟宿主的会话 tmp 不是一回事——
  两处都要在文档里写清，否则"我在容器里写了 /tmp 怎么宿主读不到"会变成 bug 报告。
- 老会话不迁移文件（本来也没多少），**按需创建**：第一次用到时 `mkdirs`。
- 删会话：**先删库再删目录**（顺序反了会留下"库里没有了、盘上还在"的孤儿）。

## 2. 跨会话访问：一个可开关的工具

**开关**：设置 → 工具与工作区 → 「跨会话读取」，默认**关**。
关着的时候这个工具**不声明**（不是灰的、不是声明了再拒绝）——不声明，模型就不会去试。

**工具**：`Session-Files`

| 参数 | 必填 | 说明 |
|---|---|---|
| `session_id` | 是 | 目标会话 id（`s_...` 那种形状） |
| `area` | 是 | `tmp` / `chat`（会话私有路径那两块） |
| `path` | 否 | 相对 `area` 的路径；缺省 = 列这一层 |
| `mode` | 否 | `list`（默认）/ `read` |

**只读**。理由：跨会话写入等于改别人的东西，而"继承一些东西"这个用途不需要写。
真要写，是另一条开关、另一轮讨论——先不摆。

**校验顺序**（每一步都要点名报错）：

1. **形状**：`session_id` 不是 `s_` 开头 + 24 位以内十六进制/数字 → 报「这一格要的是会话 id，
   形如 `s_xxxxxxxx`；从侧边栏长按会话 → 详细信息 → 长按「会话 ID」复制」。
2. **存在性**：库里没有这个会话 → 报「没有这个会话：它可能已经被删了」，
   并**不**去猜一个最像的（宁可空着）。
3. **路径**：把 `path` 规范化（`..` 弹栈）之后必须仍落在 `sessions/<id>/<area>` 里；
   越界直接拒，报「`path` 越界：`../..` 这种不行」。
4. **大小**：单次读上限 256 KB；超了报「这个文件 N KB，超过 256 KB 上限；用 `path` 取其中一段」
   （分段参数以后再加，先给一句能听懂的话）。
5. **跨助手**：允许。结果里带上「来自会话「<名字>」（另一个助手）」——
   模型得知道这不是本会话的东西，否则它会把别人的设定当自己的。

**为什么上下文里不给会话 id**：用户 2026-11-08 明确「上下文里面不会有具体的会话和 ID，
需要用户去给出会话和 ID」。所以这个工具**不**自动注入任何 id，也不做"猜你想访问哪个"。

## 3. 会话信息面板（已落，D292）

侧边栏长按会话 → 「详细信息」，一项一行，**长按复制那一项的值**：

| 项 | 值从哪来 | 备注 |
|---|---|---|
| 会话 ID | `conversations.id` | 跨会话工具要的就是它 |
| 会话名称 | `conversations.title` | 空标题显示「（没有标题）」，复制的是空串——不编一个假名字 |
| 当前版本消息总数 | `messages` 行数 | **当前版本**，不是所有版本加起来 |
| 当前版本总请求数 | 单元数（`units.total`） | 一次回答 = 一个单元；工具往返仍在同一单元里，所以它不等于消息数 |
| 当前版本用户消息数 | `role = user` 计数 | |
| 当前版本助手消息数 | 其余（assistant / tool 已折进 assistant） | |

**读不出来的时候**（会话被删、库打不开）：那一栏写「…」并补一句「这个会话读不出来」，
**不写 0**——0 会被当成"空会话"，是另一种假话。

代价：这一页要现读一次库（`load(limit = 10_000)`）。它是低频动作，可接受；
真要更快，下一步加一个 `conversation_stats` 的 FFI 查询，别在这里做缓存。

## 4. 压缩时继承 /tmp 与 /chat 里的文件

用户 2026-11-08：「上下文压缩也记得从 /tmp 和 /chat 继承相关的或者需要的文件」。

压掉的是一段对话，**压不掉的应该是"这一段依赖过哪些文件"**。所以压缩时多做一步：

1. 从这一段历史里**收集文件引用**：工具调用参数里出现的路径（`read_file` / `write_file` /
   `edit_file` / `shell` 里的路径），以及这一段的附件（`attachments` 表按消息取）。
2. 只保留**落在本会话 `/tmp` 与 `/chat` 里的**那些（工作区的文件属于项目，不属于会话）。
3. 摘要里加一节「这一段用到的会话文件」：`路径 · 一句话用途`（用途从那次调用的上下文里取，
   取不到就只写路径）。
4. 判据：压完之后问「刚才那个文件在哪」，模型答得出路径；再让它接着读，工具能打开。

不搬内容：只搬**清单**。文件本身还在盘上，摘要里塞全文等于没压。

## 5. 分批

1. **会话信息面板**（**已落**，D292）。
2. **`/tmp` 会话隔离**：工具路径映射 + 按需创建 + 删会话时一起删。
3. **跨会话读取工具**：开关 + 声明 + 五步校验 + 结果带来源会话名。
4. **压缩继承文件清单**：收集 → 过滤 → 写进摘要。

判据（每批）：core 单测 + 一条真机项。第 3 批的真机项是"复制另一个会话的 id，
让它读那个会话 `/chat` 里的一个文件；把 id 改错一位，报错点名说这是 id 形状不对"。
