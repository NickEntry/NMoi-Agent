# 每个会话一个 `/chat`（设计稿；**已被 D234 取代**）

> **2026-11-03 更新**：这份稿子里的"`workspace_mode` 两档 + 每会话一个工作区"是错的模型。
> 现在按 D234 做：工作区是**用户建的、可复用的目录**（挂在容器 `/workspace`），
> 会话自己的暂存是 `/chat`（附件在 `/chat/images`）。下面保留的是当时的推理过程，
> 别照着它改代码——尤其是 §3 那张表里的 `workspace_mode`。

> 用户 2026-11-02：「对于 /chat 是每个会话隔离的，就是每个会话看到的 /chat 都只包含该会话的，
> 这个应该做好的」。现在不是这样——**所有会话共用一个工作区**。

## 1. 现在是什么样（读代码）

`ToolingRepository.workspaceRoot()` 返回 `filesDir/workspace`，`open()` 把它交给 FFI，
`ChatScreen` 每次发请求都用同一个根。于是：

- 会话 A 的 agent 写进 `notes.md` 的东西，会话 B 的 agent 读得到；
- 删掉会话 A，它写过的文件还在，而且仍对 B 可见；
- 备份/导出按会话说话时，文件其实不跟着会话走。

容器那条路（`WorkSpace-EnvirShell`）也是同一个根绑到 `/root/workspace`。

## 2. 目标

| | 现在 | 之后 |
|---|---|---|
| 工具看到的根 | `files/workspace`（全局） | `files/sessions/<会话 id>/chat` |
| 容器里的挂载点 | `/root/workspace` | `/chat`（用户的口径） |
| 跨会话可见 | 是 | **否** |
| 删会话 | 文件留着 | 一起删（确认文案写清） |
| 共享目录 | 就是它 | 可显式绑定一个「共享工作区」，默认不绑 |

## 3. 目录与绑定

```
files/
  workspace/                        ← 老的全局工作区，保留，变成「共享工作区」
  sessions/
    <conv-id>/
      chat/                         ← 这个会话的 /chat（工具根）
      images/                       ← 附件（D216 已经落在这里）
```

- **默认**：会话在第一次发请求时建 `chat/`，绑定它。工具根 = `chat/`。
- **共享工作区**：设置里可选「绑定共享工作区」（沿用 `files/workspace`）。
  这是显式动作，不是默认——用户要的是隔离，默认就得隔离。
- 绑定存哪：`conversations` 加两列（schema v12）：
  ```sql
  ALTER TABLE conversations ADD COLUMN workspace_mode TEXT NOT NULL DEFAULT 'chat'; -- 'chat' | 'shared'
  ```
  路径不存：`chat` 由 id 推出来，`shared` 是固定根。存路径等于给"以后搬库"埋一个悬空引用。
- 老会话：迁移时 `workspace_mode='shared'`（它们的东西都在全局那份里），
  新建会话才是 `'chat'`。这样老会话不会突然"文件全没了"。

## 4. 容器那条路

`EnvirSpec::command()` 里 `GUEST_WORKSPACE` 现在是 `/root/workspace`。改成 `/chat`，
并把它绑到会话目录：

```
-b <会话 chat 目录>:/chat
-w /chat[/子目录]
```

工具描述、`guest_cwd_is_safe` 的提示、系统提示里出现的路径都要跟着改成 `/chat`。
**这是一次可见的破坏性改名**：模型看到的路径变了，老对话里写过的 `/root/workspace/...`
会成为历史文本（不影响执行，但提示词里别再教它那个路径）。

## 5. 删除、备份、导出

- 删会话：`remove_dir_all(sessions/<id>)`——`chat/` 与 `images/` 一起走。
  确认文案：「会话里的文件、图片都会从盘上删掉」。
- 备份（0.15ai 的缺口）：备份 = `.db` + **整个 `sessions/`**（图片与 chat 都在里面）。
  恢复时按会话 id 对回去。
- 导出单个会话：带上 `chat/` 的 zip（先做备份，再做这个）。

## 6. 界面

- 聊天页顶部那一条「模型 · 上下文 12%」旁边**不加**路径（太长）。
- 设置 → 工具与工作区 → 工作区：
  - 「当前会话的 /chat」一行：显示 `sessions/<id>/chat`（可复制路径）。
  - 「打开共享工作区」开关：默认关；开着时新会话绑共享目录，副标题写「关掉只影响新会话」。
  - 「清理空会话的 chat 目录」：列出 0 字节目录，确认后删。
- 存储页（D216）把 `chat/` 也算进来，按大类分时归到「会话文件」。

## 7. 边界

| 情形 | 处理 |
|---|---|
| 会话 id 里带奇怪字符 | id 是我们生成的（字母数字），不接外部输入；仍然按"只允许 `[a-z0-9]`"校验一次 |
| 目录建不出来（空间满/权限） | 发请求前就报错，别让工具跑到一半才发现没有根 |
| 两个会话同时写 | 各写各的目录，天然不冲突 |
| 用户手动把文件放进 `files/workspace` | 只有绑了共享工作区的会话看得到 |
| 备份恢复后 id 变了 | 按 id 对；对不上的目录进「未归属」列表，不静默删 |

## 8. 验收

1. 会话 A 让 agent 写 `a.txt`；会话 B 让 agent `list_dir`。**判据**：B 看不到 `a.txt`。
2. 容器里 `pwd` → `/chat`；`ls /chat` 只看到这个会话的文件。
3. 删会话 A。**判据**：`sessions/<A>/` 整个没了；B 的文件不受影响。
4. 老库升级：老会话仍是共享工作区，文件都在；新建会话是隔离的。
5. 备份 → 清数据 → 恢复：每个会话的 `chat/` 回到原位。
