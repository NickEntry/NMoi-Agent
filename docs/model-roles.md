# 默认模型、角色设置、助手级启用集（设计稿，2026-11-08）

> 用户 2026-11-08 口述 + 五张 Kelivo 截图。**分批做，每批都能单独验。**
> 这一份只管结构与语义；色板与气质仍归项目 `DESIGN.md`。

## 1. 默认模型页：把"模型"拆成几个角色

Kelivo 那一页不是"选一个模型"，是**按用途各配一个**。我们要的是同一件事：

| 角色 | 什么时候用 | 默认 |
|---|---|---|
| `chat` 聊天 | 平时发消息 | 跟随当前对话模型 |
| `title` 标题总结 | 给会话起名 | 未启用 |
| `suggest` 聊天建议 | 助手回复后给几条续写建议 | 未启用 |
| `compress` 压缩 | 上下文压缩（D90 那套） | 跟随当前对话模型 |
| `translate` 翻译 | 消息翻译 | 跟随当前对话模型 |
| `ocr` 文字识别 | 图片里的字 | 未启用 |

页面形状照图 1 / 图 2：**一角色一张卡**——图标 + 标题 + 右侧两个动作（重置回跟随 / 齿轮进设置）
+ 一句说明 + 一个"值条"（点开选模型，没选就写「未启用」或「使用当前对话模型」）。
最上面另有一张「每个对话独立模型」的开关卡：开着时在对话里换模型只影响这条会话。

**这些角色当助手使**（用户原话）：齿轮进去是一个底部面板，三样东西——
`是否开启思考`（开关）、`思考强度`、`系统提示词`（多行 + 变量提示 + 「重置为默认」/「保存」），
再加一项 `世界书`（选这一角色用哪几册）。图 3 就是标题总结模型的那张面板。

## 2. 三层"启用"，三个数字（这是最容易做错的地方）

| 层 | 存在哪 | 界面上在哪 | 含义 |
|---|---|---|---|
| 册级开关 | `files/lorebook.json` 的 `books[].enabled` | 世界书页册行 | **这一册要不要出现在「＋」的清单里**（不是"生不生效"） |
| 条目级开关 | 同一册的 `entries[].enabled` | 世界书页条目行 | 这一条参不参与注入 |
| 助手级启用集 | `assistants` 表新增列（`lorebooks` / `skills`） | 「＋」面板里勾的那些 | **真正生效的是这一层** |

所以：

- 世界书页册行写「已启用 32/32」= 这一册里条目启用数 / 总数（图 4 的样子）。
- 「＋」面板写「世界书 2/13」= **生效 2 册 / 启用 13 册**（用户原话）。
- 技能写「28/28」，另外多一行「使用全部已启用技能」——一键把启用集设成全量。

**为什么册级开关只管"显示"**：用户会攒几十册（图 4 有 13 册），全塞进「＋」里没法挑。
所以要有一层"先收起来"，再有一层"这一轮用哪几册"。

**跟助手走**：这两份启用集存在助手身上，跟助手设置页里的技能子页 / 世界书子页是**同一份数据**
（用户原话）。换助手 = 换一套启用集。

## 3. 加号面板（图 5）

一行一项，右侧是计数或 chevron：

```
技能            28/28
指令注入              ›
世界书           2/13
OCR 文字识别          ›
上下文管理            ›
```

- 世界书 / 技能：点进去是勾选列表（哪些生效）；技能页底部多一行「使用全部已启用」。
- 指令注入 / 上下文管理：各自的子页。
- OCR：跟着 `ocr` 角色走（第 1 节）。

## 4. 附件多选

- 图片：**已落**（`GetMultipleContents`，一轮上限 4 张，超出的不加并说清）。
- 文件：同一套——多选、逐个落 `attachments` 表、发给模型的是**文本或路径**（跟图片的
  `inline` / `path` 两种模式对齐，D270）。

## 5. 数据模型（决定，不是建议）

- **角色配置**放 `settings` 表，`scope="role"`、`key="<role>"`，值是 JSON：
  `{"model":{"provider":"…","model":"…"} | null, "thinking":{"on":true,"level":"…"}, "system":"…", "lorebooks":["b1"]}`。
  理由：它是"应用级配置"，不是会话数据；换设备重配一次即可，不必进导出。
- **助手级启用集**放 `assistants` 表新增两列 `lorebooks TEXT` / `skills TEXT`（JSON 数组），schema **v19**。
  理由：它跟助手是同一个生命周期（删助手就该一起没），放 settings 里删助手时要另写清理，
  容易漏成"看不见的残留"（铁律②）。
- **会话级覆盖**（"每个对话独立模型"）沿用 D271 的 `conversations.workspace_id` 那套：
  会话表加两列（`model_provider` / `model_id`），空 = 跟助手。

## 6. 分批

1. **附件多选**：图片（**已落**）+ 文件（待做）。
2. **助手级启用集 + 加号面板**：schema v19 两列、世界书 / 技能两个勾选子页、计数 `2/13`、
   技能页「使用全部已启用」。请求组装按启用集过滤（core 的 `Library::merged` 之前先筛册）。
3. **默认模型页重做 + 角色设置面板**：六个角色卡、齿轮面板（思考 / 提示词 / 世界书）、重置回跟随。
4. **请求组装接线**：title / suggest / compress / translate / ocr 各自用自己的模型与设置。
   FFI 现在只有一套 provider/model，要按角色取；压缩那条已经有 `compress` 的独立请求，
   先接它（收益最直接）。
5. **文件附件**：走 `attachments` 表 + 文本/路径两种给法。

判据（每批）：core 单测 + 一条真机项。第 2 批的真机项是"两册、一册收起、加号里只勾一册，
发一句命中它关键词的话，另一册的设定不出现"。
