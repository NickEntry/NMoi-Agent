# 默认模型、角色设置、助手级启用集（设计稿，2026-11-08）

> 用户 2026-11-08 口述 + 五张 Kelivo 截图。**分批做，每批都能单独验。**
> 这一份只管结构与语义；色板与气质仍归项目 `DESIGN.md`。

## 1. 默认模型页：六张卡，三种状态

**不设「聊天模型」那一项**（用户 2026-11-08：聊天用的模型在聊天页选，助手身上存）。

| 角色 | key | 用途 | 初始值 |
|---|---|---|---|
| 标题总结 | `title` | 给会话起名 | **未启用** |
| 聊天建议 | `suggest` | 助手回复后给几条续写建议 | **未启用** |
| 视觉覆盖 | `vision` | 发图片/视频、调「查看图片」时，先让它把内容转录成详细文字 | **未启用** |
| 摘要 | `summary` | 压缩时写摘要 | **跟随当前对话模型** |
| 压缩 | `compress` | 上下文压缩 | **跟随当前对话模型** |
| 翻译 | `translate` | 消息翻译 | **跟随当前对话模型** |

**「视觉覆盖」就是我们这边的 OCR**（用户 2026-11-08 定名）：发图片、视频，以及调「查看图片」时，
本质是应用拿一段固定提示词去调这个模型，让它把内容理解完、输出成详细自然语言描述（转录），
再把那段描述当正文给主模型。所以它不是"另一个聊天模型"，是**一条旁路**。

### 1.1 三种状态

| 状态 | 存的值 | 值条上写 | 卡片第一个动作 |
|---|---|---|---|
| 未启用 | `disabled` | 「未启用」 | **重置箭头**（↺）→ 变成「使用当前对话模型」 |
| 跟随 | `follow` | 「使用当前对话模型」 | 不显示（点了也没变化的东西不摆） |
| 指定 | `provider\|model` | 模型名 | **禁用**（⊘）→ 回到这个角色的初始值 |

两个图标的名字（用户问过）：↺ 是**重置 / 恢复默认**（reset / restore，我们用的是
`ActionIcons.RotateCcw`）；⊘ 是**禁用 / 停用**（ban / block，`ActionIcons.Ban`）。

「回到初始值」对两类角色不一样：可选型回 `disabled`（真的关掉这个功能），跟随型回 `follow`
（这三样一直有活干，没有关掉这一说）。所以 ⊘ 只在「指定」时出现，点了不会出现"看起来关了
其实还在跑"的状态。

### 1.2 模型不存在就切回初始值

读配置时校验：`provider|model` 在当前的模型清单里找不到（供应商删了、模型改名了），
**直接切回这个角色的初始值**并落盘。用户原话：「如果选择的模型不在列表不在数据，
那就直接切回默认'禁用'」。

聊天页那边同理：助手身上那个模型不在了，就显示成**未选择**，而不是继续显示一个不存在的名字。

### 1.3 卡片形状

照 Kelivo 那两张图：图标 + 标题 + 右侧动作（重置/禁用 + 齿轮）+ **值条**（点开选模型）。
选模型那一页跟聊天页用的是**同一个面板、同一份来源**（供应商 → 模型，`ModelPickerSheet`）。

齿轮进去是这一角色的设置面板（是否开启思考 / 思考强度 / 系统提示词 / 世界书），
**这一批不做**：先把卡片与三态做对，齿轮下一批跟"按角色取模型"一起接。

### 1.4 视觉覆盖关掉时

「＋」面板里不显示视觉覆盖那一项（用户原话）。同理，其它角色未启用时，它对应的入口也不出现。

## 2. 三层"启用"，三个数字（这是最容易做错的地方）

| 层 | 存在哪 | 界面上在哪 | 含义 |
|---|---|---|---|
| 册级开关 | `files/lorebook.json` 的 `books[].enabled` | 世界书页册行 | **这一册要不要出现在「＋」的清单里**（不是"生不生效"） |
| 条目级开关 | 同一册的 `entries[].enabled` | 世界书页条目行 | 这一条参不参与注入 |
| 助手级启用集 | 助手文档里的 `lorebooks`（settings `scope=assistant`，**已落**，D290）；技能等接上了再加 `skills` | 「＋」面板里勾的那些 | **真正生效的是这一层** |

所以：

- 世界书页册行写「已启用 32/32」= 这一册里条目启用数 / 总数（图 4 的样子）。
- 「＋」面板写「世界书 2/13」= **生效 2 册 / 启用 13 册**（用户原话）。
- 技能写「28/28」，另外多一行「使用全部已启用技能」——一键把启用集设成全量。

**为什么册级开关只管"显示"**：用户会攒几十册（图 4 有 13 册），全塞进「＋」里没法挑。
所以要有一层"先收起来"，再有一层"这一轮用哪几册"。

**跟助手走**：这两份启用集存在助手身上，跟助手设置页里的技能子页 / 世界书子页是**同一份数据**
（用户原话）。换助手 = 换一套启用集。

## 3. 加号面板（图 5）

一行一项，右侧是计数或 chevron：

```
技能            28/28
指令注入              ›
世界书           2/13
OCR 文字识别          ›
上下文管理            ›
```

- 世界书 / 技能：点进去是勾选列表（哪些生效）；技能页底部多一行「使用全部已启用」。
- 指令注入 / 上下文管理：各自的子页。
- OCR：跟着 `ocr` 角色走（第 1 节）。

## 4. 附件多选

- 图片：**已落**（`GetMultipleContents`，一轮上限 4 张，超出的不加并说清）。
- 文件：同一套——多选、逐个落 `attachments` 表、发给模型的是**文本或路径**（跟图片的
  `inline` / `path` 两种模式对齐，D270）。

## 5. 数据模型（决定，不是建议）

- **角色配置**放 `settings` 表，`scope="role"`、`key="<role>"`，值是 JSON：
  `{"model":{"provider":"…","model":"…"} | null, "thinking":{"on":true,"level":"…"}, "system":"…", "lorebooks":["b1"]}`。
  理由：它是"应用级配置"，不是会话数据；换设备重配一次即可，不必进导出。
- **助手级启用集**放 `assistants` 表新增两列 `lorebooks TEXT` / `skills TEXT`（JSON 数组），schema **v19**。
  理由：它跟助手是同一个生命周期（删助手就该一起没），放 settings 里删助手时要另写清理，
  容易漏成"看不见的残留"（铁律②）。
- **会话级覆盖**（"每个对话独立模型"）沿用 D271 的 `conversations.workspace_id` 那套：
  会话表加两列（`model_provider` / `model_id`），空 = 跟助手。
