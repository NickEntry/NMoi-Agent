# 实机验证：方法与顺序

> 这份是**给你（人）按着做**的清单，不是给我看的设计文档。
> CI 能证明"编得过、包出得来"，证明不了"装得上、跑得动、写下去的东西还对"。
> 下面按**失败越早越便宜**排序：先验包装对不对，再验符号对不对，再验库能不能建，
> 最后才验内容对不对。中间的某一步没过就停下，别往下跳。

## 0. 现在到底缺什么验证

| 已经验过的（CI / 本地） | 还没有任何证据的 |
|---|---|
| `cargo test --workspace`、`clippy`、`fmt`、MSRV 1.75 | APK 能不能装到手机上 |
| C 侧 ABI 277 项（`./scripts/ffi_smoke.sh`） | `.so` 会不会真的被加载（符号名、ABI、架构） |
| `:app:assembleDebug` 出包（9,462,044 字节） | 库能不能在 `/data/data/.../files/` 下建出来 |
| `cargo ndk` 交叉编译出 `arm64-v8a/libnmoi_ffi.so`（**CI 绿了才算**） | 列表里显示的是真数据还是占位数据 |

一句话：**从 APK 到"界面上的数字来自数据库"这一段，一次都没跑过。**

## 1. 什么时候需要你动手

现在就需要。这几步我这边做不了——没有设备、也没有模拟器（本机 PRoot / aarch64，无 Android SDK）。

需要你准备：

- 一台 **arm64** 的 Android 手机（8.0 / API 26 以上；只编了 `arm64-v8a` 一个 ABI）
- 打开「开发者选项 → USB 调试」，或用无线调试
- 电脑上有 `adb`（跟手机同网段，或插线）
- 不需要 root；不需要 Play 商店

## 2. 前置命令

```bash
adb devices                      # 应看到设备且状态是 device（不是 unauthorized）
adb install -r -d nmoi-debug-apk/app-debug.apk
# 包名：com.nmoi.agent（全小写，D116 统一之后与 namespace 一致；2026-10-23 之前装过的
#        com.NMoi.agent 是另一个包，先 adb uninstall com.NMoi.agent 再装，否则会并存两份）
adb shell pm list packages | grep -i nmoi
```

从 GitHub Actions 的 run 页面下载工件 `nmoi-debug-apk`，解压即得 `app-debug.apk`。

当前这一版是 **20,767,078 字节**（debug，含未 strip 的 `arm64-v8a/libnmoi_ffi.so`，11,290,352 字节）。
体积对不上说明拿的不是同一版：早于提交 `ac0247a` 的包**没有 `.so`**，
装上去只会在 V1 看到「原生层未加载」。

## 3. 验证顺序
> **更早的清单在 `docs/archive/`**：V0–V46 已归档到 `verification_old1.md`。正文只留 V47 之后（最近这几轮）。

### V47 模型批量操作（D214）

1. 供应商编辑页 →「模型」→ 右上角多选。**判据**：条上出现「全选」「反选」。
2. 点「全选」。**判据**：「已选 N 项」等于模型总数；再点「反选」变成 0 项。
3. 勾两条 →「删除」。**判据**：第一次点变成「确认删除」并提示会删几个；再点才删。
   改一下勾选，按钮回到「删除」。
4. 勾一条 →「删除」。**判据**：直接删（不需要确认）。
5. 「从端点拉取模型」→ 选择模型页。**判据**：搜索框下面有「已加入 N / 共 M · 全选 · 反选」。
6. 点「全选」。**判据**：当前列表里没加过的全部加入，计数跟着变；不卡顿。
7. 在搜索框里输入关键字（比如 `flash`）→ 点「全选」。**判据**：**只加入匹配的那几条**，
   过滤掉的不动。
8. 点「反选」。**判据**：当前过滤结果里已加入的被移除、没加入的被加入。

### V48 模型行左滑删除（D215）

1. 供应商编辑页 →「模型」，按住任意一行**向左滑**。**判据**：右侧露出红底，
   里面有垃圾桶图标和「删除」两个字；滑不到一半松手会弹回去。
2. 滑过一半松手。**判据**：停在露出状态，红底和图标完整可见（不是一片空白或卡片底色）。
3. 点红区。**判据**：这一行被删掉，列表立刻更新。
4. 滑开一行后点这一行本身。**判据**：行收回原位，不会误选成默认模型。
5. 进多选。**判据**：之前滑开的行自动收回；多选时这一行不再吃滑动。

### V49 附件落盘与存储管理（D216）

1. 发一张图（聊天页「＋ → 图片」）。**判据**：消息气泡里看得到；设置 →「存储」里有一条，
   显示会话标题、mime、大小和 `sessions/<会话>/images/<id>.<ext>` 这样的路径。
2. 用文件管理器（或 `run-as`）看 `files/sessions/<会话 id>/images/`。**判据**：图片文件真的在，
   文件名就是附件 id；`sqlite3 nmoi.db "select bytes is null, path from attachments;"` 里
   `bytes` 是 1（NULL）、`path` 有值。
3. 存储页点「导出」。**判据**：系统另存对话框出现，选一个位置后提示「已导出 N KB」，
   导出的文件能正常打开。
4. 存储页点「删除」→ 确认。**判据**：这一条从列表消失，盘上的文件也没了；
   回到聊天页那条消息还在，只是不再有图。
5. 删掉整个会话。**判据**：`files/sessions/<会话 id>/` 整个目录被清掉。
6. 用旧版本产生的库（v10，图片在 BLOB 里）升级上来：打开一条带图的老消息。
   **判据**：图照常显示；再看存储页，这条的路径已经写出来（第一次读的时候搬到了盘上）。
7. 存储页空态。**判据**：写「还没有图片附件 / 在聊天页「＋ → 图片」发一张…」，
   不是一片空白。

### V50 存储页（D217）

1. 发两张图（同一会话）+ 一张（另一个会话）。**判据**：存储页按会话分成两组，
   每组标题写「会话名 · N 张 · 大小」。
2. 看路径那一行。**判据**：真路径写成 `sessions/<会话>/images/<id>.png`；
   **不再出现 `sessions/null`**。
3. 老库里还有 BLOB 附件时打开存储页。**判据**：那一行写「还在库里（第一次查看时会搬到盘上）」，
   不是 `sessions/null`。

### V51 发送即时显示 + 流式渲染（D218）

1. 在已有会话里发一句长回答容易看出来：点发送。**判据**：输入框当场清空，
   消息区立刻出现自己那条（下面写「发送中…」），不等模型回。
2. 等回复开始。**判据**：助手的正文**逐字**长出来；先出思考的话，
   思考卡标题的字数一直在变（「思考 · N 字（还在写）」），点开能看全文且**不会自己收回**。
3. 生成中点一次 ↑（变成方块）。**判据**：提示「已请求停止…」，已收到的正文留在屏幕上，
   收尾后那条消息标「未完成 · 这一轮被中断」。
4. 让回答超过 8 KiB（或直接问一个长清单）。**判据**：开头不会凭空消失——
   屏幕上是"从头长到尾"，不是只有最后一段。
5. 让模型跑一轮工具（读文件 → 回答）。**判据**：换轮之后气泡里**只**显示新一轮的话，
   不会把"我这就去读"和最终回答拼成一段；收尾换成库里那份时**不缩水**。
6. 飞行模式下发一句。**判据**：提示失败原因；已经收到的部分**留在屏幕上**并标
   「这一轮没写完…（没存进库里，点一下收掉）」；点一下才消失。
7. 新建会话（还没有 id）里发第一句。**判据**：第一句照样立刻出现在消息区，
   不会因为页面换到新 id 而闪掉。
8. 发出去之后马上切到另一个会话再切回来。**判据**：新会话里看不到上一条的「发送中」气泡；
   切回来时如果还在跑，助手那条占位还在，正文继续长。

### V54 重试就地渲染 + 失败三选一（D227 / D228）

1. 在一段已有回答上点「更多 → 重试这一轮」。**判据**：底部**不再**出现
   「助手 / 正在生成…」那一条；那行字出现在**这条消息自己的正文位置**，
   正文逐字长出来，思考卡（如果有）也在原位更新。
2. 生成期间点这条消息的动作行。**判据**：没有动作行（复制/版本/编辑都不在）——
   屏幕上这份还没落库，那些动词指不到它。收尾后动作行回来，版本号多一版。
3. 在中间某条消息上重试（不是最后一条）。**判据**：正文长在**那一条**上，
   不会跑到列表末尾去。
4. 「续话（接着往下写）」时看那一刻（0.15av 之后续话也流式了）。**判据**：原正文还在，
   续文**紧接着**在后面长，不会先变成空白再长；连接处不多一个空格、也不少一个。
5. 飞行模式 / 断网时点重试。**判据**：弹「重试失败」三选一，默认选中「保留上一版」；
   这一轮一个字都没收到时，「保留这一版」「都保留」是灰的并写「这一版是空的」。
6. 弹窗上按返回键、点遮罩。**判据**：都不关（必须处理）。
7. 选「都保留」。**判据**：版本号变成 `2/2`，当前显示这一版（这次收到的残文），
   按 `<` 能切回上一版，两版正文都在。
8. 选「保留这一版」。**判据**：只剩一版（`1/1`），正文是这次收到的残文，上一版没了。
9. 选「保留上一版」。**判据**：版本号回到重试之前那个，正文与之前**逐字一致**。
10. 让回答中途断流（拔网线或点停止）之后看那条消息。**判据**：残文留在屏幕上，
    标「没写完 / 没存进库里」；库里那条仍是上一版（不会出现空消息）。

### V55 续话流式 + 动作行里的重试（0.15av）

1. 一条已有回答，点动作行第二颗（↻）。**判据**：直接开始重试（不再需要开「⋯」），
   正文在**这一条**上重写。
2. 在一条**没落库**的会话里（新建、还没发过）看动作行。**判据**：↻ 是灰的，
   长按出「重试这一轮（现在不可用）」。
3. 点思考块 / 工具卡那几条。**判据**：它们没有动作行（本来就没有），不会出现"能点但没用"。
4. 对最后一条助手消息点「续话（接着往下写）」。**判据**：原正文**还在**，
   续文逐字接在后面长；收尾落库后正文与屏幕上那份**逐字一致**（不多一个空格、不少一个）。
5. 让续话经过一轮工具往返（让它读个文件再接着写）。**判据**：换轮之后正文**仍然带着原正文开头**，
   不会突然只剩最后一段。
6. 对一条很长的回答（> 8 KiB）续话。**判据**：开头不会凭空消失，
   屏幕上是"全文 + 新长出来的那一段"。
7. 续话中途点停止。**判据**：已经收到的部分**已经落库**（那一版是「原正文 + 续文」的全文，
   不是只剩续文那一截），提示行说已停止；不弹三选一（取消不是失败）。
8. 断网让续话失败。**判据**：弹三选一；「保留这一版」存下来的是**含原正文的全文**。

### V56 过程块合并与折叠（D229）

1. 让模型跑一轮带两三次工具的回合（读文件 → 写文件 → 再回答）。**判据**：那几次思考/工具
   合成**一个**大块，左侧一条竖线串着，不是五张各管各的小卡。
2. 数一下大块里的项。**判据**：≥3 项时头部出现「展开更多 N 步」，N = 总数 - 2；
   点一下展开成「收起」，再点回到折叠。
3. 夹了正文的一轮。**判据**：正文把组**断开**——正文上面一组、下面一组，正文自己不算过程项。
4. 只有一次工具调用的回合。**判据**：还是单独一张卡，没有竖线、没有头部（不分组）。
5. 工具还在跑（结果没回来）时看那个大块。**判据**：**不折叠**，头部没有「展开更多」；
   结果回来、这一轮结束后才按 ≥3 的规矩折。
6. 展开一个大块 → 切到别的会话 → 切回来。**判据**：恢复默认（折叠、只留最新两个），
   不沿用刚才展开的样子。
7. 展开一个大块 → 滚到上面再滚回来。**判据**：**还是展开的**（列表回收不该丢状态）。
8. 一轮里又追加了一次工具调用。**判据**：已经展开的大块**不会自己收回去**。

### V57 每个会话自己的 /chat（D231）

1. 新建一个会话，让它写一个文件（`write_file`）。**判据**：文件落在
   `files/sessions/<这条会话>/chat/` 下，不在 `files/workspace/`。
2. 在同一个 App 里再开一个新会话，让它 `list_dir`。**判据**：**看不到**上一个会话写的那个文件。
3. 升级前就有的老会话（`shared`）打开，让它 `list_dir`。**判据**：还是原来那些文件
   （`files/workspace/` 那一份），一个都没少。
4. 抽屉长按一条会话 →「改用共享工作区」。**判据**：提示说清了"老文件不搬"；
   再发一句让它写文件，落点是 `files/workspace/`。
5. 再切回「改用独立工作区」。**判据**：菜单上那句话跟着变（现读库，不是缓存的）；
   新文件落在 `sessions/<id>/chat/`，**之前写在共享目录里的那份还在原处**。
6. 容器里跑命令（`WorkSpace-EnvirShell` 开着时）`pwd`。**判据**：`/chat`，
   而且 `ls` 看到的就是这个会话自己的文件。
7. 删掉一个会话。**判据**：`files/sessions/<id>/` 整个目录没了；
   别的会话的目录一个都没动。
8. 复制一个共享会话。**判据**：副本也是共享的（`workspace_mode` 一样）。

### V58 启动时迁移老会话（D232）

1. 装一个**旧版本**（`files/workspace` 里有文件、会话是 `shared`），再用新版本覆盖安装。
   打开 App。**判据**：弹「把老会话迁到独立工作区？」；文案里写着会话条数、
   文件数与大小；默认按钮是「以后再说」。
2. 点「以后再说」。**判据**：卡片关掉，提示「老会话留在共享工作区」；**再启动一次不再弹**；
   会话菜单里仍然能单独切。
3. 重装一次（或清 App 数据后重新造一份共享目录），这次点「迁移」。**判据**：
   按钮变成「正在迁移…」；跑完提示「已迁移 N 条会话到各自的 /chat」；
   每条会话的 `sessions/<id>/chat/` 里都有原来那些文件；库里的 `workspace_mode` 都是 `chat`。
4. 迁移之后打开一条老会话，让它 `list_dir`。**判据**：看到的是自己那份副本；
   在**另一个**老会话里改一个文件，这边不受影响。
5. 共享目录本身。**判据**：`files/workspace/` 里的文件**一个都没少**（迁移是复制，不是搬）。
6. 迁移之后新建一条会话。**判据**：它看不到老会话的那些文件（隔离生效）。
7. 把共享目录里放一个很大的文件（> 50 MB）再触发迁移。**判据**：卡片上的大小如实显示；
   迁移期间界面不卡死（在 IO 线程上跑）。

### V59 容器覆盖安装与自检（0.15ay / D233）

1. 装好环境（V52 那套），确认状态行写「自检通过 · 时间」。**判据**：`state.json` 里有
   `self_check {ok:true}`，`state_version` 是 2。
2. 弄坏它：在容器里 `rm /lib/libdl.so.2`（或用文件管理器删 `files/envir/ubuntu/lib/libdl.so.2`）。
   回环境页点自检卡里的「sh + ldd」。**判据**：状态行变成「需要修复：缺库：…」，
   且 `self_check.reason` 里点名了那个库；主按钮是「覆盖安装」。
3. 点「覆盖安装」。**判据**：进度依次是"覆盖安装：下载基础层… → 解包中… → 自检中…"；
   跑完状态行回到「自检通过」；**下载量是 33.4 MB**（不是直接复用旧的）。
4. 覆盖安装之后进容器跑 `pwd`。**判据**：`/chat`，且容器里之前自己建的文件**还在**
   （覆盖安装不删树）。
5. 覆盖安装时把网络断掉（飞行模式）。**判据**：提示「没装成：下载失败…」，
   而**原来的 rootfs 还在**（状态行仍是"需要修复"，不是"还没装"）。
6. 点「重新安装（清空后重解）」。**判据**：先弹红色确认卡，写着"容器里你自己装的东西会没掉"；
   取消之后什么都没变；确认之后才清空重解。
7. 装好之后去「工具与工作区」看 `WorkSpace-EnvirShell` 那一行。**判据**：副标题写「已装 · 自检通过」；
   弄坏之后写「容器现在起不来（原因）…」；这时发一句话让模型跑容器命令，
   **它拿不到这个工具**（不是拿到一个每次都失败的工具）。
8. 老版本装的环境（`state.json` 里没有 `self_check`）升级上来。**判据**：状态行写
   「装完之后没自检过（这一版之前装的）」；`WorkSpace-EnvirShell` 仍然可用（没自检 ≠ 坏）。

### V60 工作区与 `/chat`（D234 / 0.15az）

1. 装新版本覆盖旧版本（库里有一批老会话、`files/workspace` 里有文件）。**判据**：应用起得来；
   抽屉里的会话一条不少；打开一条老会话让它 `list_dir`，看到的是原来那些文件。
