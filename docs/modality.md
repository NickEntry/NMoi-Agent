# 上下文里的非文本模态（设计稿，未动工）

> 用户 2026-11-02 问：「上下文里面留多少文本以外的东西（图片、视频这种）？
> 图片多了会有什么影响？视频是什么情况？」这一份是**查完 + 量完**之后的结论与设计。

## 1. 现在的代码实际在做什么（读代码得到的，不是猜）

| 事实 | 位置 | 后果 |
|---|---|---|
| **历史里每一张图，每一轮都重发** | `session.rs::attach_images` 遍历整条 `history`，把每条的附件塞进 `ChatRequest.images` | 20 张图的会话，每轮多付 2–3 万 token；图越多越贵，跟「这一轮用不用得上」无关 |
| **图片不占 token 预算** | `message.tokens = estimate_tokens(&message.content)`；`budget.used` 只累加文本 | 75% / 92% 两条线对图片是瞎的；`contextPercent` 也偏低 |
| 附件落盘、库里只存 path | D216 | 省的是磁盘，不是 token |
| 只有 OpenAI 兼容端口发多模态 | `runtime.rs` 938 行附近 | 其余端口收到图会明确报「不支持」 |

一句话：**现在不是「留多少」的问题，是「全都发、还不计数」**。

## 2. 一张图到底多少钱（各端口官方口径，2026-11 核对）

| 端口 | 口径 | 1000×1000 | 1920×1080 | 上限 |
|---|---|---|---|---|
| OpenAI（patch 系，gpt-5.x / gpt-6） | `ceil(w/32)×ceil(h/32) × 倍率`，`high` 最多 2 500 patch | 1 229（gpt-6-astra，1.2×） | 2 448 | 每请求 1 500 张 / 512 MB；单图 30 000 patch 拒收 |
| OpenAI（tile 系，gpt-4o / 4.1） | `85 + 170 × 512px 块`；`detail: low` 固定 85 | 765 | 1 105 | 同上 |
| Anthropic（标准档） | `ceil(w/28)×ceil(h/28)`，长边压到 1 568、上限 1 568 | 1 296 | 1 560（压到 1456×819） | API 100 张/请求（200k 模型）、600 张（其余）；**超过 20 张后每张尺寸限制更严**（稳妥做法：长边 ≤3 000） |
| Anthropic（高分辨率档，Claude 4.7+） | 长边 2 576、上限 4 784 | 1 296 | 2 691 | 同上 |
| Gemini | 两边都 ≤384 → 258；否则按 768×768 切块 ×258 | 1 032（4 块） | 1 548（6 块） | 每请求 3 600 张 |

**影响不是线性的**：Anthropic 超过 20 张会触发更严的单图尺寸限制，原本能发的 4K 截图会被拒；
OpenAI 单图超过 30 000 patch 直接 `invalid_request`，不会自动缩。
所以「多塞几张」不只是贵，是会**整条请求失败**。

## 3. 视频是什么情况

| 口径 | 数字 | 出处 |
|---|---|---|
| Gemini 静态模式（默认，1 fps） | 每帧 258 token（默认）/ 66（低分辨率），音频 32 token/秒；**约 100 token/秒（低）/ 300 token/秒（高）** | Gemini 视频理解文档（2026-10-13 更新） |
| 1 分钟视频 | 6 000 – 18 000 token | 同上 |
| 10 分钟视频 | 60 000 – 180 000 token | 同上 |
| 1M 上下文能放多久 | 低分辨率 3 小时 / 高分辨率 1 小时 | 同上 |
| Agentic 模式 | 长视频最多省 88% token（按需取帧） | 同上，仅 Gemini 4 Argon / 3.8 / 3.6 / 3.5 Flash Lite |
| OpenAI / Anthropic | **不收视频**（只有图） | 两家的 vision 文档 |

结论：**视频不能当附件直接进上下文**。一段 10 分钟的视频就是 6–18 万 token，
而且只有 Gemini 一家收；换模型就整条请求失败。正确形状是**抽帧**（当图片发）
或**转写**（当文本发），原始视频只留在盘上。

## 4. 设计

### 4.1 先让图片被算进去

- 附件落盘时算一次 `est_tokens`（按当时选中的模型家族选公式；未知就用 1 600 并标 `estimated`）。
  存进 `attachments`（schema v12 加一列），**不在每次发请求时现算**（尺寸要解码，贵）。
- `budget.used` / `contextPercent` 把附件 token 加进去。
  这一条比「留多少」更要紧：现在两条压缩线对图片是瞎的。

### 4.2 「留多少」：默认只发最近 4 张

设置 → 会话与上下文 → **上下文里的图片**：`0 / 2 / 4 / 8 / 全部`，默认 `4`。

- 只发**最近的 N 张**（按消息时间倒序），更早的在 wire 上换成一行文本占位：
  `[图片：image/png 1080×1920，已不在上下文]`。
- 为什么默认 4：一段对话里真正需要像素的通常是「刚发的那张」和「上一张对比」；
  再往前的内容，文字里已经说过结论了。4 张 ≈ 4–6k token，能接受；
  20 张 ≈ 20–30k，等于把半个窗口喂给旧截图。
- **界面上要能看出来**：被移出上下文的那张缩略图下面加一行
  「已从上下文移除（设置里可调）」——不然用户会问「它怎么不认得这张图」。
  库里的附件不动，只是这一轮不发。
- 0 = 一张都不发（纯文本模型也能用同一个会话）；「全部」保留给「就是要它逐张对比」的场合，
  并在设置页写清代价（「20 张 ≈ 2–3 万 token / 轮」）。

### 4.3 视频：抽帧，不传原件

- 附件类型先只做图片。视频入口的文案：「视频：抽帧后当图片发（原文件留在盘上）」。
- 抽帧规则：用户选起止 → 1 fps → 最多 8 帧 → 每帧按图片走同一条预算与保留策略。
  8 帧 ≈ 4–12k token，比 10 分钟原片便宜一个数量级。
- 音频轨：转写成文本（ASR 未排期），不塞进上下文。
- 这条不做「自动理解整段视频」的承诺：那需要 Gemini 的 agentic 模式，换端口就没了。

### 4.4 压缩时先丢图

`compress` 的覆盖率判据里，图片块是最该先丢的：它贵、而且文字摘要里通常已经写了结论。
顺序：**先移除超出「最近 N 张」的图 → 再按段压缩文本**。图片不参与「原文不能丢」的校验
（它不是原文，是附件）。

## 5. 可运行的核对脚本

三个公式写死在一处，落地时它同时是单测的参照：

```python
import math

def openai_patches(w, h, budget=2500, mult=1.2):
    # 先按长边 65535 压，再按 patch 预算等比压
    scale = min(1.0, 65535 / max(w, h))
    w, h = w * scale, h * scale
    if math.ceil(w / 32) * math.ceil(h / 32) > budget:
        scale = math.sqrt((32 * 32 * budget) / (w * h))
        w, h = w * scale, h * scale
    return math.ceil(math.ceil(w / 32) * math.ceil(h / 32) * mult)

def openai_tiles(w, h):
    # 压进 2048 方框；短边超过 768 就压到 768
    s = min(1.0, 2048 / max(w, h))
    w, h = w * s, h * s
    if min(w, h) > 768:
        s = 768 / min(w, h)
        w, h = w * s, h * s
    return 85 + 170 * math.ceil(w / 512) * math.ceil(h / 512)

def anthropic(w, h, long_edge=1568, cap=1568):
    s = min(1.0, long_edge / max(w, h))
    w, h = w * s, h * s
    return min(cap, math.ceil(w / 28) * math.ceil(h / 28))

def gemini(w, h):
    if w <= 384 and h <= 384:
        return 258
    unit = math.floor(min(w, h) / 1.5)
    return 258 * max(1, round(w / unit)) * max(1, round(h / unit))

for (w, h) in [(1000, 1000), (1920, 1080), (3840, 2160)]:
    print(w, h, openai_patches(w, h), openai_tiles(w, h),
          anthropic(w, h), anthropic(w, h, 2576, 4784), gemini(w, h))
```

跑出来：`1000×1000 → 1229 / 765 / 1296 / 1296 / 1032`，
`1920×1080 → 2448 / 1105 / 1568 / 2691 / 1548`。

**这是近似**：Anthropic 的真实缩放规则（`How Claude resizes and pads images`）比我这里写的细，
它自己的表里 1920×1080 标准档是 1 560 而不是 1 568。落地时每个端口各写一份，
fixture 用**官方文档里的那张表**，不要用这个脚本当真理。
