# notes —— 给 AI / 开发者看的

设计思路、决策记录、验证清单、踩过的坑、计划，都放这里。**用户不看这些**。

两条约定：

- **面向用户的写在 `docs/`**，用户手册以那边为准。
- **两边都有用的**：正文只写一份、放 `docs/`，这里留一句指向它（`见 docs/xxx.md`）。
  反过来复制一段过来，等于两份迟早对不上。

- `decisions.md`：D 编号，为什么这么选、否掉了什么。
- `PLAN.md`：0.1x 那些行，做到哪、没做什么。
- `verification.md`：真机清单（V 编号）。
- `lorebook.md` / `voice.md` / `message-parts.md` …：分主题的设计稿。
- `archive/`：按 200 KB 切的旧文，编号不重排。

## 记录到什么程度（2026-11-15 用户定）

- **变更不另立文件**：不写 `*-变更.md`、不按日期开新稿、不在文档里写"某年某月某日改了什么"。
  每一次改动 git 里都有；文档里再抄一遍，就是两份会说不一样话的记录。
- **只在有必要时记**：决策留"为什么这么选、否掉了什么"（`decisions.md` 的 D 编号）；计划留一行
  （`PLAN.md`）；真机清单留 V 编号。过程、试错、当天做了什么，不记。
- **设计并进已有章节**：内容不长就接在那一节后面，别为一条改动新开一章。
  章节越碎，读的人越要先猜"这条在哪"。
- **`docs/` 只有用户参考**：不给 D 编号、不写取舍、不写历史。要讲"为什么"，来 `notes/`。
