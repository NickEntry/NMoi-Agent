# 字体策略（P6.5 / D68）

> 一句话：**默认用内置的 OFL 字体，用户可导入自己的字体（单槽，换走即删），也可以跟随系统。**
> 全部内置字体都是 SIL Open Font License 1.1——可商用、可嵌入、对应用本体没有传染性。

## 1. 内置什么

| 用途 | 字体 | 许可 | 体积（实测/量级） |
|---|---|---|---|
| 中文正文与 UI | **Noto Sans SC**（思源黑体同源） | OFL-1.1 | Regular 单文件 **8.3 MB**（SubsetOTF） |
| 拉丁正文与 UI | **Inter** | OFL-1.1 | 单字重 ~300 KB |
| 代码 / 路径 / 工具输出 | **JetBrains Mono** | OFL-1.1 | 单字重 ~200 KB |
| 品牌与标题（少量） | **得意黑 Smiley Sans**（工作区已有） | OFL-1.1 | **2.6 MB** |

**得意黑不用于正文**：它是斜体展示字（Oblique），笔画夸张、重心偏，12–14px 会糊；
放在标题、空状态、关于页正好，放在消息正文里会让人读得累。它自带中英文（拉丁区 334 字、CJK 8057 字，
实测），所以标题里中英混排不需要第二套字体。

**为什么不用"免费商用"那批（MiSans / HarmonyOS Sans / 阿里普惠）**：它们的许可是厂商自拟的，
写着"免费商用"但保留解释权与随时修改权。我们要的是**能被独立验证的许可文本**——
OFL-1.1 是 OSI 认可的、有固定条款的，出了争议拿文本说话；自拟许可只能拿"当时页面这么写的"说话。

## 2. OFL 的三条义务（写进 `NOTICE`，二进制里也带着）

1. **保留版权行**（字体 `name` 表的 nameID 0）与许可文本，随包附一份 `OFL.txt`。
2. **不得单独售卖字体**（卖整个应用没关系）。
3. **改动过的版本要改名**（Modified Version 不能用原字体名）。

第 3 条正好和"导入即改名"是同一件事，见下。

## 3. 用户的三个选项

| 选项 | 行为 |
|---|---|
| 内置（默认） | 用上面的字体，回退链 `Inter → Noto Sans SC`（拉丁走 Inter，中文缺字回退 Noto） |
| 跟随系统 | Android = 系统默认（唯一选项）；Windows = 字体列表 + 搜索；Linux = fontconfig 列表 + 同一搜索框 |
| 导入字体 | 选一个 `.ttf/.otf/.ttc` → 复制进应用数据目录 → **内部名改写为 `Imported Font`** → 立即生效 |

### 导入字体的规则（用户 2026-10-21 提的）

- **存储位置**：`<appdata>/fonts/imported.ttf`（单槽）。
- **自动改名**：写入时把 `name` 表的 nameID 1 / 4 / 6 / 16 改成 `Imported Font`。
  这样既避开与内置字体重名，也天然满足 OFL 第 3 条（改名后仍保留原版权行）。
  改写失败（字体格式特殊）时**回退到只改展示名**并在 UI 上说明——不要假装改成功了。
- **切换即删**：切到内置或系统字体时，删掉 `imported.ttf`；重新导入时覆盖旧的。
  单槽是故意的：多槽会立刻变成"字体管理器"，那是另一个产品。
- 导入的字体**不参与**中文回退——用户选的就是它，缺字就显示缺字（豆腐块），
  免得"我明明选了 A，怎么中文变成别的字体"。

### 系统字体列表：三个平台怎么拿

| 平台 | 手段 | 注意 |
|---|---|---|
| Android | **不给列表，只给"系统默认"** | 厂商字体族名不稳定，列举出来一半点不动；兼容优先（用户原话） |
| Windows | DirectWrite `IDWriteFontCollection` 枚举 family（含本地化名） | 必须**带搜索框**（用户明确要求）；族名中英双语都能搜到 |
| Linux | fontconfig（`FcFontList`；兜底 `fc-list : family`） | 没有 fontconfig 的极简环境回退"系统默认"；搜索用同一套过滤 |

Rust 侧倾向用 `font-kit`（Windows=DirectWrite、Linux=fontconfig 各有后端），
但它会带进一串依赖——**先记着，实现时再定**（D10 要求依赖锁版本并写理由）。

## 4. 排版细节（不写下来就会被每个平台各实现一遍）

- 正文 14px / 行高 1.45；辅助文字 11.5px / 1.35；标题 15–20px。
- **数字用 tabular-nums**：token 数、时间、上下文窗口那几行要对齐。
- 只用 Regular / Medium 两档。`font-weight: 600/700` 会让系统合成假粗体（笔画糊、字宽变），
  宁可换颜色或字号。
- 中英混排不额外加空格：Noto Sans SC 与 Inter 的标点宽度都按西文体设计，自动间距已经够。

## 5. 现状

- 图标与草稿：`docs/ui/icons/thinking-*.svg`（7 个）、`docs/ui/draft-composer.svg`、`docs/ui/draft-desktop.svg`。
- **字体文件本身还没进仓库**（`assets/fonts/` 未建）：Noto Sans SC 8.3MB 属于要单独想一想的体积，
  子集化（GB2312 6763 字 ≈ 2.5MB/字重）留在真正打包前做。
- 导入/系统字体是**设计已定、未实现**：Android 需要 SAF 选文件，Windows/Linux 需要平台枚举 API，
  两者都要等有工具链的机器（本机没有）。
