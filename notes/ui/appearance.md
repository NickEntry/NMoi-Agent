# 外观：主题 / 自定义主题 / 背景

> 2026-10-23 用户提的三条：① 页面背景黑白可切；② 给"自定义主题"预留预览位；
> ③ 聊天页支持图片背景与动态（视频）背景，**背景跟着助手走**，换掉之后旧文件要清掉。
> **状态（2026-10-23）**：主题三态**已实现**（`ThemeMode` / `ThemeStore` / `NMoiTheme(dark)`，
> 冷启动底色按主题选）；背景与自定义主题**只有形状与灰行**，代码没写。

## 1. 主题：三态，不是两态 —— **已实现**

`跟随系统` / `深色` / `浅色`，默认跟随系统。

- **为什么三态**：手机日落自动切深浅的人不少。只给两态，等于逼他每天来手动点一次。
- 两套 token（`DarkColors` / `LightColors`），组件里**不写死颜色**；现在 `theme/Theme.kt`
  只有 `darkColorScheme()`，`NMoiTheme` 加一个 `dark: Boolean` 就够。
- 深色不是"把浅色调暗"：背景取 `#101014` 量级、卡片比背景抬一档、正文不用纯白（`#E6E6EA`），
  避免 OLED 上的光晕和"夜里刺眼"。
- 图标包的 `backing: surface` 规则（D105）要在两套主题下各验一遍：白底图标需要垫底这件事，
  只在浅色下成立。
- **系统栏要单独告诉系统，而且是三件事**：窗口底色、状态栏底色、图标深浅。
  没开 edge-to-edge 时，状态栏那块区域显示的就是窗口底色——只在 `onCreate` 设一次的话，
  应用内切主题后那块还是启动时的颜色（深色主题下状态栏仍是亮的，真机上就这么被看出来的）。
  现在合成一次 `applySystemBars(window, dark)`，主题变化时整组重设。
- `isAppearanceLightStatusBars = true` 表示系统栏底色是浅的、图标画深色。
  只改应用内颜色不改这一条，浅色主题下状态栏图标还是白的，等于看不见（真机上踩过）。
- 验收：系统切深浅，应用不重启跟着变；正文对比度 ≥ 4.5:1、次要文字 ≥ 3:1；
  浅色下状态栏的时间 / 电量 / 返回箭头是**深色**，看得清。

## 2. 自定义主题：**只留位，不做实现**

外观子页多一行「自定义主题」：灰行 + 一条三色预览条（背景 / 卡片 / 主色），点不动，写"待接"。

预留的数据形状（5 个颜色封顶）：

```json
{ "kind": "custom", "bg": "#101014", "surface": "#1A1A20",
  "primary": "#8AB4F8", "on_surface": "#E6E6EA", "on_surface_variant": "#9AA0A6" }
```

- **为什么只给 5 个**：给 40 个 token 等于给他 40 次调坏的机会，调坏了还得自己排查对比度。
- 存储要一个新 scope `appearance`（D86 现在是 model_overrides / assistant / conversation / roles）。
  加 scope 要动 core 的 `Scope::parse` 与 schema 的 CHECK，**排进 1.0 之前，不顺手改**。
- 预览只在那一行里出效果，**不整屏预览**：整屏预览会闪，而且用户改的是"设置"不是"应用"。

## 3. 背景：纯色 / 图片 / 视频，按助手归属

### 3.1 归属

背景跟**当前助手**走：`settings(scope=assistant, key=<assistant_id>)` 的 doc 里加 `background` 字段。

助手还没接线时先用 `key="default"`；接线那年写一条一次性迁移（`default` → 默认助手的 id），
**不做两套并存**——并存意味着每个读背景的地方都要判两次。

```json
{ "background": { "kind": "video", "file": "bg/ab12cd34.mp4",
                  "fit": "cover", "dim": 0.25, "muted": true } }
```

- `dim` 是压暗层（0–0.6），为了文字压得住背景；默认 0.25。
- 文件路径相对 `files/backgrounds/<assistant_id>/`，文件名 = 内容哈希前 16 位 + 扩展名：
  同一张图选两次不会存两份。

### 3.2 清理（用户点名的硬要求）

换种类（视频→图片→纯色）、换文件、删助手，都要把旧文件删掉；再在启动时扫一遍
`files/backgrounds/**` 里**没有被任何助手 doc 引用**的文件。

- 引用集从 settings 表读（`assistant` scope 全部 doc 的 `background.file`）。
- 清理失败**不阻断界面**，但要在调试日志留一行（否则以后"空间去哪了"查不出来）。
- 判据：换掉视频后 `adb shell run-as com.nmoi.agent ls files/backgrounds/<id>/` 里旧文件消失。

### 3.3 尺寸预算

- 图片：按屏幕尺寸 + `inSampleSize` 解码，长边 ≤ 2048，缓存一份在内存里。
- 视频：见下，≤ 720p。

## 4. 视频背景：性能怎么做

**只用平台解码，不引 ffmpeg。** 理由两条：LGPL/GPL 与体积都不划算；而且省电那条路是**硬解**，
硬解本来就要走 `MediaCodec`，引不引软件解码器都一样。

### 4.1 入库时转码一次（平台 API，无新依赖）

`MediaCodec` + `MediaMuxer`：

| 项 | 取值 | 为什么 |
|---|---|---|
| 编码 | H.264 baseline（首选）/ HEVC（同画质更省码率，硬解覆盖稍差） | 兼容性与省电的折中 |
| 分辨率 | ≤ 1280×720 | 手机铺满屏够了；4K 在低端机上必掉帧 |
| 帧率 | ≤ 30 | 背景不需要 60 |
| 码率 | ≤ 2 Mbps | 5 秒循环 ≈ 1.2 MB |
| I 帧间隔 | 1 s | 循环点附近必须有关键帧，否则每次循环都要重解一大段 |
| 音轨 | **丢掉** | 省一半码率；背景本来就没声音 |

### 4.2 播放

- 单实例复用：`MediaPlayer.setSurface(TextureView.surface)`，`isLooping = true`。
- **不可见就停**：页面切走、抽屉全开、应用进后台 → `pause()` 并释放解码器持有的 surface；
  回来 `resume()`。这是省电的主要来源，不是可选项。
- 硬解不可用 / 解码失败 → **降级到首帧静态图**（画面不能黑，黑屏比没有背景更糟）。

### 4.3 与"系统动态壁纸"不是一回事

`WallpaperService` 做的是**桌面壁纸**，要常驻进程、耗电，而且跟"跟着助手走"的语义对不上。
聊天页背景只在聊天页内部渲染，不进系统壁纸位。这条写清，免得以后被当成没做。

## 5. 验收判据（真机，现在一条都没跑）

| 项 | 判据 |
|---|---|
| 主题 | 三态切换即时生效；两套下文字不糊不刺眼；杀进程重开保持 |
| 背景归属 | 切到另一个助手，背景跟着变；切回来还是原来的（助手接线后才可验） |
| 清理 | 换掉视频后旧文件消失；再启动一次不会"复活" |
| 重启 | 杀掉应用重开，背景还在 |
| 视频流畅 | 进出抽屉 / 进设置 / 回桌面再回来，不该有重新起播的卡顿；连续 5 分钟，记下 `dumpsys gfxinfo` 掉帧与 CPU |
| 降级 | 人为给一个坏视频，应退到首帧静态图而不是黑屏 |

**未实测**：低端机 720p 铺满的帧率、硬解并发被系统抢走时的表现、转码耗时（30 秒视频大概多久）。

## 6. 明确不做

- 整屏自定义主题编辑器（先只给 5 个颜色）。
- 视频音轨与播放控制条（背景不是播放器）。
- `WallpaperService` / 系统壁纸位。
- 在线壁纸源（不联网取图，用户自己选）。
