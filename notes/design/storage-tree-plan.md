> 就不适合在存储管理这里清）」

> 然后集中在这里，可以用这两种分类页面快捷的预览和删除操作什么的」

这份是**计划**。现在的 `StorageDetailScreen.kt` 对十项用的是同一个模子（平铺文件列表），
那是错的——十项其实是**三种东西**，混在一个模子里每一种都别扭。

---

## 0. 一句话

| 形状 | 哪几项 | 点进去是什么 |
|---|---|---|
| **树** | 沙箱环境、技能、工作区文件、会话文件 | 一级是"根"，之后是正常目录结构，能一层层下 |
| **卡片** | 缓存、日志、其他、聊天记录 | 不是文件列表，是几张卡，每张卡有自己的动作 |
| **平铺 + 快捷操作** | 图片、文件 | 与「会话文件」同一批东西按类型聚了一份，给快捷预览与删除 |

判据只有一条总的：**同一个文件在这三种页面里出现时，路径必须一致**——
否则用户会以为盘上有两份。

---

## 1. 树形：四个根

### 1.1 沙箱环境

```
沙箱环境
  rootfs/            ← 容器的根目录，点进去就是 /（usr bin etc …）
  tmp/               ← 容器里 /tmp 的宿主侧（D294 起按会话隔离，这一份是全局的）
```

- 一级只有两项，**不是**把 `files/envir/` 摊平（那里面还有 `state.json`、`resolv.conf`、
  `bin/`、`lib/`，那些是"运行时的零件"，不是用户要看的）。
- `rootfs/` 点进去 = 容器根目录，一层层下（`usr/` → `lib/` → …）。
- **只读**：这一层不给删除、不给改名。要动它去「环境」页（那里有重置/修复，走确认卡）。
  理由：`rootfs` 删掉一个文件，容器就起不来了，而"删一个看起来没用的文件"是这一页最容易
  被当成安全动作的地方。

### 1.2 技能

```
技能
  NeteaseMC-Developer-skill/
  MC-BEres-Skill/
  …
```

- 一级是 `files/skills/` 底下的**目录名**，点进去是那个技能的文件树。
- 每行副标题写 `N 个文件 · X MB`（现算）。
- 删除：一级可以删（整个技能目录，走确认卡，写清"这个技能会从列表里消失"）；
  进去之后**不给删单个文件**——一个技能少一个 `SKILL.md` 就废了，而那种坏法在界面上看不出来。

### 1.3 工作区文件

```
工作区文件
  Default/           ← 默认工作区（files/workspace）
  w1a2b3c/           ← 名字取自 .nmoi-workspace.json
  …
```

- 一级是**工作区名**（不是 id），点进去是那个工作区根下的正常目录结构。
- 默认工作区固定第一行，标一个「默认」徽标（它不能改名、不能删，`WorkspaceRepository` 那条规矩）。
- 删除：进去之后可以删文件（走工作区那套越界检查，用 `nmoi_workspace_delete_json`），
  一级**不给删整个工作区**——那是「工作区」页的事（一个动作一个入口）。

### 1.4 会话文件

```
会话文件
  AI客户端开发-37 · 0199f0c3/     ← 标题 · 短 id
  新对话 · 0199f0d1/
  …
```

- 一级是**会话**，名字是 `标题 · 短 id`（短 id = UUID 前 8 位）。
  **同一标题的两条会话必须能分开**——这是这条唯一的硬判据。
  标题为空写「（没有标题）」。
- 点进去只有两层（`chat/` 与 `tmp/`），再进去是目录结构：

```
会话文件 › AI客户端开发-37
  chat/          ← 用户发来的（attachments/）与 AI 写的输出
  tmp/           ← 这一条会话自己的 /tmp（D294）
```

- 里面**不出现** `images/` 与 `archive/`：前者归「图片」，后者是归档原文（`/archive/<hex>.txt`），
  它属于"这条会话的上下文"，不属于"用户会去翻的文件"。
  这一条要写进注释，否则下一轮会有人"顺手补全"。

## 2. 卡片：四个

卡片页的共同点：**没有文件行**。判据是"这一页里一行文件都没有"，
有就是写错了（那说明它该是树形或平铺）。

### 2.1 缓存

```
缓存
  系统缓存
    67.4 MB · 缩略图与临时文件
    [ 清理 ]
  可清理 67.4 MB
```

- **只有一张卡**：「系统缓存」。点「清理」= 清空 `cacheDir` 里的内容，
  **不删 `cacheDir` 本身**（7z 导出的临时包、备份的临时库都落在那儿）。
- 卡上一句"清理不会影响使用：缩略图与临时文件会按需重建"。
- 清完当场把大小刷成 0 并提示"已清 X MB"。
- **不给逐文件列表**：缓存里的东西名字是哈希，列出来只会让人不敢清。

### 2.2 日志

```
日志
  上下文日志     12.3 KB    [查看] [清理]
  网络日志       0 B        [查看] [清理]
  运行日志       48.1 KB    [查看] [清理]
```

- 三张卡，对应 `LogKind` 的三个通道（`context` / `request` / `debug`）。
- 「查看」进已有的 `LogChannelScreen`（那里有查看/复制/导出/清除四个动作）——
  **不另写一个查看器**。
- 「清理」走确认卡（删了就没了，而日志是排查用的）。
- 上限与开关不在这页（在「调试 → 日志设置」里，一页一件事）。

### 2.3 其他

```
其他
  本地模型
    还没接 · 等本地推理那一层
    （灰着，不给假开关）
```

- **只有一张卡**：「本地模型」。这一版还没有本地模型（`AppSettings` 里没有那一项），
  所以灰着并写清等哪一层。**不摆点了没反应的开关**。
- `files/vault/`、`files/voice/` 那些也归「其他」，但**不进卡片**——
  它们是"App 自己的零件"，不是用户会去点的东西。它们只计进大小。
  这一条与「十项之和 == 总和」不冲突：`kindOf` 照样把它们算进 `Other`。

### 2.4 聊天记录

```
聊天记录
  聊天数据库     299.87 MB   nmoi.db
  写入日志       4.76 MB     nmoi.db-wal
  共享内存索引   32.0 KB      nmoi.db-shm
  [ 备份 ]
  删了就没有聊天记录了；要清会话请去侧边栏长按。
```

- 三张卡，**只给看与备份，不给清理**（用户原话："毕竟能在侧边栏长按清理会话，
  就不适合在存储管理这里清"）。
- 备份那颗按钮是这一页唯一的动作（D424 提速之后才敢放上来）。
- 卡下那句要写出来：**别让用户在这一页找删除**。

## 3. 平铺 + 快捷操作：图片与文件

```
图片
  （按会话分组，每组一行小标题）
  AI客户端开发-37 · 12 张
    0199…/images/a.jpg   1.2 MB
    …
文件
  AI客户端开发-37
    chat/attachments/3e4f-a.txt   2.1 KB
    tmp/out.log                   88 KB
```

- 数据源**就是** `/chat` 与 `/tmp` 底下那些（与「会话文件」同一批），
  只是按**类型**聚了一份：图片 = `images/` 下的，文件 = `chat/attachments/` + `tmp/` 下的。
- 目的只有一个：**快捷预览与删除**（用户原话）。所以这一页保留平铺、保留多选、保留长按菜单。
- 每行副标题必须写出**它在会话目录里的相对路径**（`chat/attachments/…` / `tmp/…`），
  否则用户不知道它属于哪一条会话。
- 判据：这里删掉一份，去「会话文件」对应会话里也看不到了（同一个文件，不是副本）。

## 4. 实现形状

### 4.1 拆文件

现在 `StorageDetailScreen.kt` 是 595 行、一个 `kind` 参数分十支。改成：

```
StorageDetailScreen.kt     入口 + 按 kind 分派到三个形状 + 共用的行组件
StorageTreeScreen.kt       树（一层一层下，自己维护 currentPath）
StorageCardsScreen.kt      卡片（四种卡，各自的动作）
StorageFlatScreen.kt       平铺（图片 / 文件，多选 + 长按菜单 + 7z 导出）
```

`StorageFlatScreen` 基本就是现在的 `StorageDetailScreen`（多选/长按/导出那一套已经写好了），
搬过去改数据源就行。

### 4.2 树的每一层要**现读盘**

不用打开时抓的快照：删完文件返回上一层，数字还是旧的，用户会以为没删掉。
判据：删一个文件 → 返回 → 那一行的大小变小（不是"要重进一次才变"）。

### 4.3 大小怎么算

树的每一级都要显示 `N 个文件 · X MB`。**现递归算**（App 私有目录，几千个文件一秒内）。
不给缓存：缓存要失效逻辑，而这一页是低频动作。

### 4.4 判据清单

1. 树形页每一层的条目大小之和 == 上一级报的数（不能有"看得见但没算进大小"的）。
2. 「会话文件」一级的名字是 `标题 · 短id`；同一标题的两条会话能分开。
3. 卡片页里**一行文件都没有**（缓存 / 日志 / 其他 / 聊天记录 四页各看一次）。
4. 聊天记录页**没有删除按钮**，只有备份。
5. 图片/文件页每一行都能在「会话文件」对应会话里找到同一份（同一路径）。
6. 沙箱环境与技能进去之后**不给删单个文件**（沙箱只读；技能只在一级给删）。
7. 删一个文件返回上一层，大小当场变。

### 4.5 真机项

V186：四个树形页各下两层；V187：四个卡片页各看一眼（没有文件行、聊天记录没有删除）；
V188：图片/文件删一份，去会话文件里确认也没了。
