## 0. 这一份管什么

现在「设置 → 存储」只有一页：`StorageScreen.kt`，按会话分组列图片附件（D216 那批）。
用户要的是 kelivo 那种**分项账本**：一页看得见"这台设备的空间都被谁占了"，每一项点进去
能看见明细、能清理。

四件事：

1. **存储空间根页**：一段占比条 + 一行一项（图片 / 文件 / 聊天记录 / 缓存 / 日志 / 其他 /
   工作区文件 / 沙箱环境 / 技能 / 会话文件），每项带大小与箭头。
2. **每一项的子页**：明细（哪几个文件、多大、什么时候）+ 清理动作。
3. **长按菜单**：任何一条文件行，长按出「多选 / 删除 / 导出」。多选后底部动作条
   可以批量删除、批量导出。
4. **导出 = 标准压缩等级的 7z**（用户原话）。备份（`nmoi.db`）也走这条路。

## 1. 与 kelivo 的差别（不照抄的地方）

| kelivo 的做法 | 我们怎么做 | 为什么 |
|---|---|---|
| 一条彩色占比条，图例挤成两行小字 | 占比条保留，但**图例只列前五项**，其余并进「其他」；点图例能跳到对应子页 | 十项图例在手机上一屏放不下，第二行会被切 |
| 「共发现可清理空间 2.60 MB」 | 改成「可清理 X MB」，**点它直接进清理动作** | 一个数字放在那儿不能点，等于装饰 |
| 子页顶部两个圆角胶囊按钮（查看日志 / 清理日志） | 主操作放右下角一颗浮动动作，其余进 `⋯` | 一屏一个填色按钮（界面册那条） |
| 「正在检查附件使用情况…」占一行 | 骨架行，保持行高 | 一行字出现又消失，列表会跳 |
| 图片页顶部两组筛选（类型 / 排序）各占一行胶囊 | 合成一行：类型 chips + 排序图标按钮 | 两行胶囊把首屏吃掉三分之一 |
| 删除按钮是红色描边胶囊 | 破坏性动作走文字 + 确认卡，红色实心只出现在确认卡里 | 同上 |

**加的功能**（用户明确要的）：长按菜单「多选 / 删除 / 导出」；多选删除；多选导出 7z。

## 2. 数据从哪来（每一项都要能指出路径）

| 项 | 路径 | 怎么算 | 能不能删 |
|---|---|---|---|
| 图片 | `files/sessions/<id>/images/` | 逐文件 `length()` 求和 | 能（按会话 / 按文件） |
| 文件 | `files/sessions/<id>/chat/attachments/` | 同上 | 能 |
| 聊天记录 | `files/nmoi.db` + `-wal` + `-shm` | 三个文件分别列出来 | **不能删**（只能备份后重建） |
| 缓存 | `cache/` | 同上 | 能（清空即可，系统会重建） |
| 日志 | `files/logs/` | 同上 | 能 |
| 其他 | `files/` 下没被上面任何一项认领的 | 差值 | 能（逐文件） |
| 工作区文件 | `files/workspace/` + `files/workspaces/<id>/` | 同上 | 能（按文件，走工作区那套越界检查） |
| 沙箱环境 | `files/envir/` | 同上 | 能（走 EnvirRepository 的删除流程） |
| 技能 | `files/skills/` | 同上 | 能（按目录） |
| 会话文件 | `files/sessions/<id>/chat/`（输出那部分） | 同上 | 能 |

**判据只有一条**：这些数字加起来必须能对上 `files/` 的真实占用（允许差值 < 1%，
差值就是"其他"）。对不上说明有一类东西没被认领——那正是铁律②要挡的
（"存了但看不见"）。这条要做成单测。

## 3. 分批

### 第 1 批：根页与统计（不依赖真机）

- `StorageUsage.kt`（纯逻辑，可单测）：给定"一组 (路径, 大小)"，算出十项的大小与占比、
  以及"其他"的差值。**判据**：`storage_usage_covers_everything`——把所有文件塞进去，
  十项之和 + 其他 == 总和。
- `StorageRepository.kt`：走 `File.listFiles()` 递归（App 私有目录，不需要越界检查），
  在 IO 线程跑，报进度。
- `StorageScreen.kt` 重写成根页：占比条 + 十行。
- 判据：真机上数字与 `du -sh` 对得上（V184）。

### 第 2 批：子页（每项一页，共用一套组件）

一个 `StorageDetailScreen(kind)`，`kind` 决定标题、数据源、可用动作：

- `images` / `files`：文件行 + 缩略图 + 多选
- `chat` / `cache` / `logs` / `other`：文件行 + 单文件动作
- `workspaces` / `envir` / `skills`：目录行，点进去是那个目录的文件列表
- `sessions`：按会话分组的行

**不给每个子页各写一屏**：它们的差别只有"数据从哪来、能做什么"，那两样是参数。

### 第 3 批：长按菜单与多选

- 长按一行 → 底部浮层：多选 / 删除 / 导出（三项，不是一排图标）。
- 进多选后：行首换勾选框、底部换 `BulkBar`（删除 / 导出 / 退出），
  与抽屉那套一致（`ConversationSelection` 的判据可以照搬，但文件 id 是路径）。
- 判据：动作落在哪一条，屏幕上就得在哪一条上看得见（界面册那条）。

### 第 4 批：7z 导出（core 已落，D425）

- `nmoi_sevenz_write_json`：给一组 `{name, path}`，写一份 7z 到目标路径。
  流式写（`sevenz::write_to`），报进度。
- 单文件导出：包内只有一个条目（用户原话"依旧是标准压缩等级 7z"，所以不另给 zip）。
- 判据：导出的包用系统解压器能打开、内容逐字节一致（`scripts/check_sevenz.sh` 已验）。

### 第 5 批：备份提速（已落，D424）

`crates/storage/src/backup.rs`：步长 64 页 + 每步睡 10 ms → 8192 页不睡。
246 MB 的库：**14.6 s → 2.3 s**（含验证）。

## 4. 不做的事

- 不做"自动清理"的定时任务（用户没提，而且后台定时清理删除用户文件风险太大）。
- 不删 `nmoi.db`：它只能备份后重建，界面上那一项**不给删除按钮**，只给「备份」。
- 不做"清理未使用附件"的引用分析：`attachments` 表已经是唯一真源，盘上没有库记录的文件
  就是"输出"，不该被当成垃圾——那是 AI 写的。
